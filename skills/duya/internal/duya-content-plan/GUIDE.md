# 线索获客选题生产与内容规划

把用户的观点、知识、经历、问题或原稿，发展为合适的人愿意看、看完确有收获、能够认识作者专业价值的内容。也完成起号、日常更新与系列规划。选题不是一个标题，而是**对谁，在什么处境下，用什么材料，讲清什么，让他得到什么**。

## 先识别本轮需要完成到哪一步

| 用户给了什么 / 要什么 | 本轮怎么做 |
|---|---|
| 一个想表达的点、理论、观察 | 还原表达目的，发展解释或方法，构造选题；要成稿就接着完成 |
| 原稿或参考视频 | 提取原意、有效表达与事实；判断是表达问题、交付不足还是方向分歧，再改 |
| 已选定方向 / 已认可小样 | 接续已确认的主线，直接制作；不要重新给一套方向让他选择 |
| 只要标题、开头或局部修改 | 保留正文任务和事实，直接改指定部分；不启动全套研究 |
| 不知道拍什么 / 一周或系列安排 | 从当前业务、真实素材和客户疑问安排有区别的内容；需要时深做其中一条 |
| 连续觉得“不对、没劲、再来几条” | 回看原始任务和认可项，检查是否选错内容任务或观看期待，再决定改哪层 |

已有材料自行提取，不发空白业务问卷。小请求直接完成；复杂内容需要确认的是**会改变成品的选择**，不是每一步操作。

## 读取范围

- 从想法发展选题、深改长稿或反复改偏：读 [选题生产方法](../../knowledge/content/topic-production.md)。
- 原意模糊、材料抢了主线或多轮修订失准：再读 [创作修订案例](../../references/topic-production-cases.md) 对应部分。
- 起号/一组内容/泛垂直与业务关系：读 [内容任务](../../knowledge/content/content-task-map.md)。
- 本轮需要吸引、共鸣、开头与正文组织：读 [网感与情绪](../../knowledge/content/attention-emotion.md) 对应部分；完整创作应主动使用，不等用户说“没网感”才补。
- 外部理论需要查证：按 [资料使用](../../references/knowledge-use.md)；需要参考表达时按 [模板工具](../../references/template-tools.md) 检索。已有充分材料，不为证明调用过工具而重复检索。

## 1. 先提取内容任务，主动帮用户想清楚

在内部保留：用户想持续建立的认识与本次表达的点；受众的具体处境；看完希望他能理解、判断、选择或做到什么；作者主张；已有事实和有效原句；长度/形式/制作限制；认可与否决项。已有定位沿用，没有长期战略不强迫重做定位。

**区分“提到什么”和“要教会什么”。** 用户反复提到模型名，不代表只要模型科普；原稿包含抱怨，也不代表要写立场对抗。模型可以是讲懂的对象，也可以是解决问题的工具。知识、判断、经历、演示可结合，以主要交付决定主次，不强制互斥分类。

有两种以上解释会明显改变受众期待或正文时，先给 2—3 个真实不同的方向，每个含：**一句开头示例 + 看完得到什么 + 简短推荐理由**。例如“理解一个模型”和“用模型学会筛人”需要不同正文。用一句具体问题让用户选择，不问“你想要什么风格”代替判断。

只确认这一项关键分歧，给用户机会回答后再写依赖该选择的长稿；可继续整理事实、核对资料。用户已明确方向或要求直接出稿时，沿用选择或简述最有依据的理解后完成。确认不是固定审批流程。

## 2. 深挖出值得讲的新判断

根据问题进入相关领域，选择真正有解释力的角度。可以从行为、激励、决策、信息、组织、经济或技术约束研究，不按学科凑名单。用万流归因诀找可能的原因，比较它们会导向怎样不同的处理。

研究应改变以下至少一项：原先的问题定义、原因判断、适用条件、观察标准、行动方法。只多了一个理论名，不算深化。

把结果写成具体关系：“在什么条件下，什么安排通过什么机制导致什么现象；因此该看什么、改什么”。解释机制与证明因果分开。需要最新事实或学术背书时核对一手来源；无研究工具时不伪称已检索，先用可支持的材料完成。普通观点和创作不以用户提供论文为前提。

知识方法类内容继续把“有责任心、专业、性价比”等抽象标准翻译为：**在哪个场景，看什么行为，怎样比较，何时换判断**。用例子让观众能实际应用。相关演示、经历或直接答案已能完成任务时，不强塞科学理论。

## 3. 扩展相关性，守住内容交付

从专业说法，找到目标客户或相邻人群已经熟悉的处境、得失、选择、反差。扩大的是进入同一个问题的理由；不是为了覆盖更多人，换一个正文答不了的大话题。

逐条候选检查：“被这一句吸引的人，接下来最想知道什么？”把这份期待与正文交付对照。教选人，就让观众想知道怎么看人；讲公平立场，才围绕公平展开。双向冲突、情绪嘴替、利益疑问是可选方法，不是必用结构。

## 4. 构造选题与材料关系，同时设计传播

确定一句核心表达。把材料分清：兴趣材料让人进来；解释材料把关系讲清；事实证据支持某个具体判断；方法/演示让人会用。相同材料可兼任，不能让最刺激的材料取代本条任务。

围绕观众自然产生的问题安排正文：为什么与我有关 → 原来困惑在哪 → 这个判断为什么成立 → 我怎么看/怎么用。此顺序可按素材调整，不做固定四段模板。每段应接住前文的疑问或有意义地推进，不只是“提供了新信息”。

在构造中比较观看、继续看、记住、分享和认识作者的理由。能指出具体句子/例子/方法在哪里发挥作用；不写“增强共鸣”“制造悬念”就算完成。分享需要说清材料能帮谁解决什么或表达什么，不能靠站队扩大人群。

## 5. 选出真正对题的候选，必要时给小样

先排除改变用户主张、制造事实、吸引错期待的候选，再比较具体相关性、值得解释的差异、内容回报和可实现性。**最刺激的候选不自动胜出。** 同时不以“对题”为借口退回课程目录式开头。

默认给一个推荐方向，只有真实取舍才给少量备选；用户明确要多条按需提供。候选要改变入口或观察角度，不是同义句换词。长稿存在方向分歧时，小样含开头、自然承接、正文准备教会什么，而非一串孤立钩子。用户一旦选定，沿用其选择完整展开。

## 6. 完成稿件或规划，不把内部步骤甩给用户

用户要完整短视频就接 [视频制作](../duya-video/GUIDE.md)，内部携带内容任务、核心主张、材料职责、受众期待、认可/否决项、长度与真实事实，不让用户再输入一个命令。需要长文/图文则接相应能力。只要选题，就交选题及足够判断是否值得做的说明。

系列安排应让各条解决不同疑问或推进不同判断；保留各条独立可懂，不把三十个近义标题当内容系统。排序按现有材料、客户相关性和制作负担给依据，不虚构爆款概率。

## 7. 多轮修改与交付检查

每轮保留原始目标和用户最新认可项。先判断反馈影响的是方向、知识交付、入口、展开、口吻还是长度。改“太短”应补解释与方法；改“没劲”应找具体缺口，不能自动加对立。用户否决某类方向后，后续不换个措辞重新推荐它。

出现反复否定或意图冲突，回到原文和已选目标，给一个对照例子辨别偏差；不要求用户自己诊断 AI 的问题。不把最近一版 AI 稿当唯一真源。

交付前须读实际内容，回答：

1. 它仍在表达用户真正要讲的东西吗？开头吸引的期待与正文是否同向？
2. 观众看完具体多会了什么；关键抽象标准有没有判断办法？
3. 这版最值得看的具体发现、场景或变化是什么；为什么推荐它而非另一候选？
4. 每段怎样让理解或观看继续推进；是否靠重复填满时长？
5. 即使去掉末尾广告，潜在客户还能认识作者哪项相关能力？

成稿与研究备注分开。没有发布数据就评价文本与方法，不报告预测完播率或保证十万播放。用户给业务反馈就用，没给不建立强制追踪工作流。
