# 公众号文章创作、改稿与排版

内部能力：为当前业务、课程、案例和观点写真正可用的公众号文章，也能把已有文章做成可预览、可复制的公众号排版稿。写作与排版按用户当前需要组合，不要求每次从商业诊断开始。

## 先识别这次要做什么

| 用户当前要求 | 执行方式 | 保留边界 |
|---|---|---|
| “帮我写一篇公众号文章” | 写作：理解材料、形成主张、完成正文 | 没有要求排版时，直接交文章，不强制选主题 |
| “这篇不要改字，帮我排版” | 只排版：读取原文、选择主题、生成 HTML 和预览 | 不增删段落、不改事实、报价、作者、引用和原文标点，不追加 CTA 或签名 |
| “写好后直接排成公众号格式” | 写后排版：先完成正文，再以这份正文作为排版输入 | 一次交付正文与排版文件，无须用户重复发起排版任务 |
| “只改开头”“这段改得具体一点”“把标题样式换一下” | 局部改稿或样式调整：只处理指定范围 | 不重写整篇，不重新诊断业务；样式变化不顺带改正文 |

“润色并排版”包含改文授权，但改文仍受事实与范围约束；保留可核对的正文稿，说明实质修改。“只排版”与“保留原文”优先于主题的装饰建议。用户没有说明主题时，根据文章题材和已有偏好选一套直接执行，交付时简短说明即可。

## 读取与输入

写作或内容改稿时读[公众号长文知识](../../knowledge/content/wechat-longform.md)。需要具体共鸣/开头/分享动机时读[网感与情绪](../../knowledge/content/attention-emotion.md)相应部分。用户给新课且需理解或核对冲突时，调用量子阅读的必要部分；普通文章不强制深度研究全库。

取已有主题、读者、真实素材、主张、品牌表达、已确认偏好和目的。只有主题仍可先形成有条件的主张与不编故事的解释文；关键产品事实不能猜。不要把所有背景重问一遍。

排版时读[公众号排版执行规范](../../references/wechat-typesetting.md)与[主题选择指南](../../references/wechat-themes.md)，使用当前 Skill 内的主题资产和脚本。12 套主题是视觉选择，不是 12 个新 Skill。仅排版时不必先补商业背景或读取全部写作知识。

Markdown 或纯文本可以直接准备为输入文件。Word、PDF、网页富文本需要先用宿主实际具备的读取工具提取，保留转换稿并检查段落、图片、表格、引用；没有相应工具时说明具体读取限制，不能声称仅凭路径已经读取。资料有缺页或提取失败时，不凭猜测补成原文。

## 完成文章

1. 说清当前读者为什么愿意读、读后获得什么判断。主张需要实质内容，不强行反常识。
2. 选择与材料相配的结构：问题重定义、真实案例、方法说明、理念与选择、资料解读。顺序由论证关系决定，不统一套“痛点—三点—升华”。
3. 对关键主张配事实、解释、例子或条件；教学例明确为示范，不写成用户经历。引用保持原意，资料中作者夸张说法不直接当真理。
4. 回应真正会改变判断的异议。不要假设所有不购买者都不懂价值，也不要用一例证明所有客户。
5. 把段落写完整，按关系推进。删重复口号，保留具体细节、必要复杂性和用户自己的表达。
6. 根据任务决定产品联系。观点/科普可以不卖；商业文可说明产品实际帮助哪里，不能捏造资质、案例、名额和结果。

## 排版执行

1. 确认当前正文版本，保留原文件。已有 Markdown 结构按原结构映射；纯文本不擅自补标题、摘要、目录、编号或结尾。
2. 用户指定主题就使用对应主题；未指定时按文章选一套。需要看效果再选时可生成 12 主题对照页，不把浏览全部主题设成必经步骤。
3. 通过 `tools/wechat_layout.py` 生成正文 HTML、预览页与校验报告，命令见[执行规范](../../references/wechat-typesetting.md)。标题、作者、摘要参数只填用户已提供或本次写作已确定的内容，不自动补占位信息。
4. 处理校验错误，并检查排版内容有没有遗漏、重复、顺序变化；检查窄屏下标题、引用、列表、表格、图片和代码的阅读效果。只有预览截图或脚本校验时，不能宣称已在公众号编辑器实测。
5. 优先给用户预览页，同时提供干净正文 HTML。告诉用户复制预览中的正文后到公众号编辑器粘贴，实际检查图片、表格、链接和样式。预览工具栏不能进入正文。

主题只控制视觉表达。不要为了“有设计感”对每段自动划重点、把删除线改成高亮、改变中文标点、重排论证、自动增加英文标签、编造图片说明或追加获客话术。新增重点和引导文案只有在用户要求时处理。部分主题为二级标题添加视觉序号；原 H2 已有编号时不重复添加。用户要求不编号或严格保持原有视觉结构时，使用 `--no-numbering` 关闭主题新增编号，原文中的编号仍保留。

## 交付

默认标题与完整正文；摘要、封面文案、配图、排版稿按用户需求添加。用户要详细就写充分，篇幅由材料与问题决定；不机械固定字数。若要长文，只给提纲不算完成；若只改开头，不重写全篇。

需要排版时交付实际生成的预览页、正文 HTML 与校验状态，不能只给代码示意。用户只要局部样式变更时，交付更新后的文件和变化点。Python 或文件工具不可用时如实交付已完成部分，说明还差哪步；不要把未运行的 HTML 草案当作已经校验的成品。配图说明不等于图片已生成。

## 质量判断

文章有没有清晰主张和阅读回报？每一部分是否推进了理解？材料能否支撑结论？对象有没有从老板跳成消费者？有没有凭空出现“前几天一个客户”？产品联系是否符合事实？

能够具体指出并改正这些问题才叫深度改稿，不用“去 AI 化”分数或加口头禅代替判断。不根据文章写完就承诺分享和获客结果。

排版另外检查：所选主题是否帮助阅读？层级能否分清？强调是否克制？正文是否保持完整？用户是否能打开并复制？报告是否仍有未处理警告？脚本检查通过只证明本次静态检查通过，不证明平台将完整保留所有样式，也不代表文章内容已通过事实审查。
