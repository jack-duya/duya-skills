# 线索获客选题生产：从想表达的东西到观众能带走的判断

适用：用户有一个想法、知识、原稿或真实经历，需要发展成有深度、有传播价值、与获客相关的内容；也用于多轮修改仍不满意的情况。局部修辞请求只用有关部分，不必走完整流程。

这是来自创作修订与既有内容研究的实践方法，不是已验证的爆款算法。来源与边界见 [来源说明](../SOURCES.md#source-topic-process)，具体正反例见 [修订案例](../../references/topic-production-cases.md)。

## 1. 创作对象是什么

一个主题，可以形成完全不同的内容。都提到“权责利”，可能是在教管理模型、教筛选负责人，或表达职场分配立场。主题词相同，不代表内容任务相同。

将原始想法发展为选题，需要形成三层关系：

- **表达方向**：作者希望持续让别人理解什么；这次保留什么真实立场。
- **本条交付**：哪个人遇到什么事，看完更能理解、判断、选择、操作或感受到什么。
- **进入方式**：用哪个具体事件、反差、疑问、体验或演示，让这些人愿意进入。

进入方式可以大幅改造，本条交付不能在不知不觉中换掉。新的研究确实推翻原判断时，应说明关键依据并提出调整建议；尊重表达意图不等于维护错误事实。

选题可以来自敏锐观察、长期经验、咨询、材料、知识联想或实际搜索。不能只等灵感，也不能把榜单上的标题当选题本身。AI 的工作是发展、比较、验证与组织这些原料，不宣称能替代作者全部经验。

## 2. 内容类型帮助确定交付，不是给用户贴标签

| 主要任务 | 看完应得到什么 | 需要形成的材料 | 容易误改成什么 |
|---|---|---|---|
| 理解机制 | 明白现象为何出现、什么条件下成立 | 困惑、关键关系、解释与区分案例 | 名词科普、无依据的单因解释 |
| 学会判断或操作 | 知道看什么、怎么比较、怎样做 | 标准、可观察信号、动作、例子、适用边界 | 只讲“要主动、要专业”的口号 |
| 形成观点 | 知道作者支持什么、理由与取舍 | 立场、现实代价、解释与反例 | 强加操作教程，或凭空制造敌人 |
| 理解经历 | 看见当时选择、过程、代价与认识 | 真实事件、变化、细节 | 替作者编情节、冒充普遍规律 |
| 观看演示 | 看懂变化、关键动作或判断依据 | 可见过程、对照与必要解释 | 没有画面仍假写实拍，或硬讲理论 |

同一条可以组合。关键是明确哪个是主交付，哪个用于支持它。“知识型”不等于满篇术语，“观点型”也不低于知识型。选错任务才是问题。

## 3. 怎样帮不会策划的人想清楚

先自行读材料，提取问题、立场、重要事实与有效原句，不让用户重填。用一句容易判断的话复述理解：“你希望看完的人能……，这个模型主要用来……”。信息清楚时直接推进，不必展示内部分析表。

当同一素材确实能导向不同主交付，给可感知的选择：

| 方向 | 开头小样 | 看完的收获 |
|---|---|---|
| 讲懂模型 | 为什么事情已经交出去了，团队还是等老板做决定？ | 理解责任、权限、回报怎样配合 |
| 教会判断 | 提拔了业务最强的人，为什么老板反而更忙？ | 学会怎样观察、验证负责人能力 |
| 表达立场 | 每个决定都要批准，最后却让你独自担责，这合理吗？ | 对一种管理安排形成明确态度 |

这是方向对照教学例，不是三选一固定菜单。先给符合原稿目的的推荐，再确认关键分歧。不要用“理性还是感性”“知识型还是观点型”这类抽象词让新手猜。也不要让用户在十八条看似不同、实际同一方向的开头里纠错。

好的确认只有一个决策负担：“你更希望观众学会具体选人方法，还是先理解模型？”已经回答过就不再问。用户要直接完成时，按当前证据最强的方向写并简述理解；用户明确要先讨论或先选方向时，给小样后等待，不能默认代选长稿。

## 4. 深挖怎样形成真正有价值的发现

深挖的产物是关系、机制、区分或方法；理论名字和参考数量只是研究材料。

“新判断”是相对这群观众已有的认识而言，可以是基础知识被讲透，不要求每次发明新理论或故意反常识。作者原本已经判断得准确时，把它讲清、教会就是深化，不必为了展示研究推翻原意。

### 从现象进入

先分开可观察事实、作者对原因的解释、作者想达到的状态和准备用的办法。针对能改变行动的不同原因展开，不机械穷尽所有原因。

例如“负责人总问下一步”可能涉及任务能力、决策经验、授权、信息可得性或工作安排。原稿只给了提问行为，就不能写成“已证实老板不放权”。但可以提出观察办法，区分不会、不敢与没有权限。最后是否以授权为主线，还要看内容任务与材料支持。

### 从知识进入

用户只有概念时，寻找它能解释的具体困惑：谁在做什么选择，直觉会怎么判断，在哪个条件下这个知识给出不同解释，差别为什么重要。找不到有意义的现实关系时，应换例子、缩小命题或提出另一角度，不能加术语假装深刻。

### 研究角度按需选择

| 角度 | 追问什么 | 可能改变的判断 |
|---|---|---|
| 行为与激励 | 当前安排让哪种行为更有利、更省力或更可控？ | 把“人不行”的笼统归因拆成可检查条件 |
| 信息与决策 | 各方知道什么、如何评估、哪里无法判断？ | 区分实际价值与被看见的价值 |
| 成本与替代 | 付出的不只是标价，还有什么时间、机会或负担？ | 解释不同人为何选择不同方案 |
| 组织与流程 | 谁能做决定、调资源、协调和承接例外？ | 找到单点能力与整体推进的区别 |
| 技术与操作 | 哪个环节改变结果，怎样看见、对比或验证？ | 把抽象承诺变成可操作的标准 |
| 人的经验与关系 | 谁承担什么、期待什么、什么没被说清？ | 用具体处境呈现情绪，避免无事实的敌意 |

以上是检索视角，不是科学定律，也不是每题必须覆盖的六格。选最贴切的少数角度深做。

### 形成研究结论

内部留下足够复用的内容：

> 现象与疑问 → 主要解释和竞争解释 → 关键区分 → 可以观察什么 → 因而怎样判断/行动 → 条件与未知。

对需要外部依据的论点，核对一手研究、官方资料或原始案例，保留它实际支持什么、不能支持什么。理论能解释一种关系，不等于已验证这个案例的原因，更不等于能预测流量。核对来源的工具不可用，就明确研究范围，不编作者、论文、数据或因果结论。

研究应在判断够清楚、反例不再改变本条结论时收束。不要因为“深度”无限拓展学科，拖延用户要的作品。

### 把知识做成能用的方法

“有责任心”是品质名，不是观众能直接使用的标准。进一步问：什么场景能看见它？哪些行为支持判断？哪些别的原因会造成同样表现？下一步怎样验证？

同样，“装修要透明”要落到报价范围怎么对齐；“选题要懂客户”要落到同一素材对客户与同行分别解释什么；“内容要有价值”要落到观众多会作出哪个判断。未必每条都列步骤，但承诺教方法就要真正教会。

## 5. 扩展人群要扩展相关性

可以沿着“专业术语 → 实际处境 → 更多人理解的得失或疑问”寻找入口。每往外一步，都用正文兑现检查来决定是否继续扩展，不以人口规模最大为目标。

例如专业主题“负责人能力识别”，可以让准备升任管理者的人自查，也可以帮助带项目的人识别协作伙伴。共同问题是“个人做得好，能否带着事情往前走”。如果改成“谁给的钱少、谁就不值得负责”，虽然仍能提到权责利，观看期待已换了。

内部为有竞争力的候选补两句话：

- 他因为这句开头，会期待听到什么答案？
- 我现在的正文，靠哪一个判断或方法回答它？

若需要换掉主体和大量正文才能回答，这通常是另一个选题；除非用户认可新方向，不用它替代当前作品。

泛垂直不排斥情绪，也不等于一味扩圈。搜索型内容可以直接回答专业问题；讲给同行的内容可以用术语；过程演示可以从视觉变化进入。不同任务需要不同观看理由。

## 6. 核心和辅助材料怎样分配

用一句话写出主交付，再为重要材料分工。不是强制给用户展示表格，而是防止材料争夺中心。

| 材料作用 | 该做的事 | 不该替代的事 |
|---|---|---|
| 兴趣入口 | 让观众认出问题、看见反差或想知道后续 | 不能因为有冲突就改掉原意 |
| 解释 | 讲清关键关系，让判断有理由 | 理论名不代替具体推理 |
| 支持证据 | 支持某个限定的事实或结论 | 单个案例不能证明普遍必然 |
| 应用方法 | 让人能观察、比较、采取行动 | 清单名不代替怎样使用 |
| 收束与连接 | 回到已完成的认识、作者能力或真实业务 | 不能在结尾突然卖一个正文无关的服务 |

删掉一段会失去什么？如果只是少了一次同义强调，压缩；如果失去了理解关键关系的桥，保留。模型、案例、数据不按“权威程度”排序，按观众此时需要它做什么排序。

## 7. 传播与共鸣从构造时开始

不要先写完一堂课，再在前后包上刺激句。构造每个关键段落时，同时处理：

- **进入理由**：哪项具体处境、利益、困惑或变化值得停下？
- **共鸣理由**：理解了什么真实成本或没说清的感受？不必认同观众所有归因。
- **继续理由**：观众接下来想知道什么，这一段如何兑现或推进？
- **记忆与使用**：能带走哪一句准确判断、哪个动作或可观察的标准？
- **分享用途**：谁可能把它给谁看，为了解决什么、讨论什么或表达什么？这是设计假设，不是声称人一定转发。

不必每条都有五种作用。方法型作品可以靠有用区分和好例子持续吸引；演示靠变化；经历靠选择和后果。人际对立只是很小的一种材料，不是传播的代名词。

“研究充分”与“表达强”可以并存。普通成稿无需附论文出处，也不应塞满“可能、或许、一定程度”。需要条件时把条件说具体：“每一次小测试都要批准时，负责人就很难独立推进。”缺事实时用明确的设问、类比或假设，不编精确统计或亲历。

## 8. 候选生成和候选选择是两项工作

先用不同观看理由生成少量真正不同的方向，再选择；不要仅换形容词。评价顺序是：

1. 对不对题：主张、主交付、受众期待有没有被偷换？
2. 接不接得住：正文和素材能否兑现？有没有新编事实？
3. 强在哪里：哪项具体差异、处境或回报比普通介绍更值得看？
4. 能否完成：用户的材料、表达方式和时长能承接吗？

前两项不成立的候选，不能靠“更抓眼球”获选。通过前两项仍然平淡的候选要继续创作，不以正确替代吸引力。

对历史候选应保存“为何选、为何弃”的简短依据。这样收到“更强一点”时，能在同一内容任务内升级，而不是重新追逐最刺激的选项。

小样应至少让用户看见开头怎样接正文，以及正文交付什么。单句选中了，并不意味着后续可以改成另一个主题。不存在关键分歧或用户要求完整稿时，直接交稿，无需固定先选小样。

## 9. 知识长稿怎样形成观看推进

把正文放回观众可能产生的疑问中检查。例如：

> 为什么提拔能干的人仍不省心？ → 两种能力差在哪？ → 具体看哪些行为？ → 招聘/提拔时怎样看见？ → 选到人后还要配什么？ → 最终如何让业务有人承接？

这是一条适合负责人筛选的推演，不是通用六段公式。其他内容可以从结果、操作、疑惑或演示开始。

有新信息仍可能无聊：此时观众不需要这个信息，或前提未交代，或与主线无关。每段不只是“增加信息”，还应有阅读位置上的理由。合理的复现可以帮助记住，不把所有重复一律删除；也不把“第一第二第三”一律判为说教。

长度服从用户要求与信息量。需要长稿时补足解释、案例、应用和关键条件，不用反复总结填时长。字数与时长只能估计，读稿试拍才能确认，不能把未经试读的长稿标成精确六分钟。

## 10. 多轮修订怎样不丢方向

保留一份轻量创作记录即可，不建 CRM 或让用户交作业：原始目的、当前确认的主交付、核心表达、已选开头、事实、素材职责、长度、否决项。单轮小改直接用上下文；长任务需要保存时遵循项目记忆规则，原始私有内容不写入公共技能库。

| 用户反馈 | 先检查什么 | 对应动作 |
|---|---|---|
| “不是我要表达的” | 原意/主交付/立场 | 回原文，提取并用小样区分，不继续润色旧中心 |
| “有道理，但没用” | 是否只有抽象结论 | 补观察办法、例子或实际操作 |
| “开头不行” | 听不懂、无关、平淡、期待偏题中的哪一项 | 改对应原因，候选仍服从同一任务 |
| “还是不行” | 同一方向局部强化是否失效 | 主动提出可能的方向分歧并给具体对照 |
| “太短” | 原有知识交付哪些没展开 | 补解释和应用，不把它视作认可全部上稿 |
| “选这个” | 用户选择的究竟是哪一句/哪条方向 | 记录并完成，不重新抽签 |

用户的短反馈是局部信息，不是全盘认可。已经明确的新意图应覆盖旧假设；没被用户确认的 AI 解释不能越改越像事实。

## 11. 交付标准与线索获客的关系

作品至少做到：忠于已确认意图；有具体观看理由；兑现所承诺的知识或体验；材料可信；作者的相关能力在正文可见。知识方法的获得感，本身可以建立信任，不需要每次结尾加咨询口号。

若作者希望吸引线上获客团队的经营者，采用他能解释的真实业务情境、清楚的判断与办法，有助于让相关人知道他擅长什么。这是内容设计上的联系，不能等同于已获得有效线索。没有产品信息时在内容价值处结束，不编服务。

需要检索模板时，查匹配或相邻赛道的表达机制，并检查它是否适合当前任务。模板有情绪但会改立场就弃用；模板中的播放、客户故事和服务承诺不能继承为自己的事实。

## 12. 内部可复用的深挖指令

以下可作为复杂选题研究时的工作提示，不必原样展示给用户，也不要每条内容完整运行。

> 依据当前材料和已确认意图，先指出本条到底要帮助谁理解或做到什么。把主题词、现实问题、核心主张、模型、案例的职责分开。列出会改变全文的真实歧义；没有就直接推进，有就用开头与交付示例帮助用户判断。
>
> 找出最值得讲清的关系或区别。选择相关领域深入研究，比较真正会改变行动的解释；查证需要外部支持的主张，记录适用条件与反例。不要把每个学科都套进来，也不要用理论名代替解释。
>
> 将发现翻译为观众能观察、比较、选择或执行的办法；用已有事实与明确示意的例子说明。寻找更多相关人群已知的处境，扩大观看理由，逐一检查这些期待能否由同一正文兑现。
>
> 给核心与辅助材料安排职责。让观众的疑问推动信息出现，同时设计具体的兴趣、共鸣、继续观看和记忆理由。先剔除偏题候选，再比较吸引力，推荐有实质优势的一条。
>
> 按用户范围交付选题、小样或完整稿。保留其已选主张、开头、事实与长度。若连续修改仍无效，回看原始目标和已确认项，辨别是否在错误方向上优化。研究备注与可发布文案分开。
