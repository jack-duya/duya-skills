# 公众号：用完整论证与真实材料建立判断

适用：写公众号文章、把案例/课程/观点改为长文、重写空洞文章、形成业务理念文章。本文负责真正写作；有排版工具时可另行生成排版稿，不能只交 HTML 外壳。

## 1. 一篇文章为什么值得读

先从资料或上下文确定读者目前怎么理解这件事，他愿意读是为了得到答案、解释、判断、经验还是立场。形成一个能用一句话说清的主张，不必刻意反常识。如果主流观点本来对，就提供更具体的条件、难点和实践，不造一个稻草人来反驳。

例如“做获客别只盯账号数量”不足以支撑长文；“当内容还在回答同行的问题时，增加账号会扩大同一种错配；当内容已经吸引适配客户而地域覆盖不足时，扩张才是另一个问题”有条件和可展开的判断。

来源：[GZH](../SOURCES.md#source-gzh) 93–152、270–275。认知旅程是内部构思方法，不要求每篇输出“动摇—建立—升华”标签。

## 2. 根据材料选文章结构

| 材料/任务 | 更合适的结构 | 必须注意 |
|---|---|---|
| 想澄清一个误解 | 具体处境→原解释哪里不够→更准确区分→例子→行动选择 | 不把可能原因写成唯一原因 |
| 有真实项目 | 当时的业务与选择→为何这样做→变化→新的问题→可用条件 | 保留失败与其他因素，不只挑漂亮结果 |
| 有产品理念 | 客户在乎的问题→我们的选择标准→做法/证据→谁适合 | 不是创始人自传拉长或品牌形容词合集 |
| 有系统方法 | 一个实际问题→分层解释→关键步骤与对照→局限→使用方式 | 每一段都提供新信息，不用标题堆砌冒充体系 |
| 学了一门课 | 来源与问题→关键主张→解释与冲突→对当前业务的启发 | 区分老师原话、编者解释和本次建议 |
| 已有短视频 | 找可展开的疑问→补论证/材料→回应异议→成文 | 不能只加连接词和段落来凑字数 |

篇幅由问题深度和材料决定。短文能讲清就短；用户要详细文章且资料足够就写充分。不要默认 2000–5000 字，不因为“公众号”而每段写成金句海报。

## 3. 论证如何变厚

每个关键结论至少有对应的说明方式：真实例子、可核事实、明确比较、逻辑推导或条件分析。没有证据时可以用标明是假设的例子帮助解释，但不能让它承担“已经证明”的功能。

材料薄时按这个顺序补实：

1. 把抽象名词换成具体场景，说明影响谁的什么选择。
2. 解释为什么有此关系，中间哪个环节容易被省略。
3. 给一个反面条件：什么时候这条建议不成立。
4. 给一项当前能做的动作，而不是只喊理念。

例如“要打造信任”可以展开为：读者可能认可你讲知识，却不知道服务是谁做；展示实际执行的人和一次判断如何形成，能补充不同信息。如果用户没有相应团队事实，不能替他编“每单老板亲自审核”。

有证据不代表摆满数据。数字需要对当前主张有用；案例需要解释发生了什么；引用需要保留来源和原意。避免把课程自述收入、历史分润或平台说法写成通用事实。

## 4. 开头与推进

开头可以从一个具体决定、一段真实原话、一组确有依据的差异、一个读者正在面对的问题进入。不要无根据写“昨天一位客户找我”，也不要固定“最近很多人问我”。

段落推进用问题关系：上一段指出什么，下一段为什么必须接着解释。例如：账号数量→扩大什么内容→内容吸引谁→实际服务谁→什么条件下该扩大分发。这比“首先/其次/最后”串五个平行口号更有阅读驱动。

转场要写出联系，不只加“然而”“因此”。如果材料之间没有真实联系，宁可删掉。保留能让人停下来理解的具体细节，不把全部故事压成抽象结论。

## 5. 示范片段：账号问题的商业文章

以下为本版教学稿片段，不是访谈实录或已发生的客户案例：

> 想多买几个账号时，先想清楚：你准备把什么放大。
>
> 如果现有内容一直在教同行怎么做，十个账号可能只是让更多同行看到。换成一百个，也没有自动变出一百倍准备购买的人。
>
> 但另一个方向也容易说过头：并不是账号少就天然更专业。已有内容能吸引适合的客户，新门店却覆盖不到，或者现有团队已经可以持续产出真实素材，增加账号与合作分发就可能有理由。
>
> 两种情况看起来都叫“账号不够”。前者缺的是内容与客户的连接，后者缺的是把已有能力送到更多相关人面前的方式。
>
> 因此，先看你最近在讲谁的事。不是只看标题有没有“老板”两个字，而是看例子、画面和最后给出的建议，究竟是谁会用。

后续若要完成整篇，应基于用户材料展开具体内容改法与自营/合作分发的条件，而不是再重复“由果推因”四遍。商业联系来自判断，结尾是否有产品介绍取决于用户目标与实际服务。

## 6. 分享价值与业务联系

分享可能因为帮助别人、表达立场、认出自己、保存一份可用材料。这是构思视角，不能据此预测分享率。给一个真实可用的判断，通常比结尾“建议收藏转发”更重要。

产品连接可以自然解释：这个问题用户自己能先做哪一部分，实际服务再帮助哪部分，适合谁。不把整篇铺成隐形广告，不在事实还没讲清时急着报价。用户只要科普/观点文章时，完成该任务即可。

来源：GZH 326–350；[J](../SOURCES.md#source-j) 1219–1275、1753–1771。

## 7. 改稿与交付

改稿定位到内容：哪里只重复结论、哪个案例没有支撑主张、哪段混了受众、哪句是假事实、哪一异议值得回应。需要全篇就交完整全篇，不能只留“补案例”的括号。

默认交标题与完整正文。摘要、封面文案、配图位置、排版稿按实际需求加；配图建议不等于已生成图片。保留用户表达偏好与已否决说法，不每次把文章改回统一的 AI 咨询口吻。
