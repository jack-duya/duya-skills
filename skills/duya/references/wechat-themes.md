# 公众号主题：12 种文章节奏

主题的作用是帮助读者理解内容：快速找到判断、顺着步骤执行、分辨对话声音，或者读完一篇长文。先看文章要让读者做什么，再选构图、章节与引述方式，最后确定颜色。

12 套主题的机器配置以 [themes.json](../assets/wechat/themes.json) 为准。使用流程与交付要求见 [公众号排版](wechat-typesetting.md)。主题只改变呈现，不擅自改写作者的观点、案例、数据或行动引导。

## 主题速查

| 主题 / ID | 适用内容 | 构图与阅读节奏 | 章节与引述 |
| --- | --- | --- | --- |
| **渡鸦简报** · `raven-brief` | 获客策略简报、行业动态、方法结论 | 左对齐报头；无衬线；平衡留白，让读者先抓住结论 | 横线分节；边线引述；不自动编号 |
| **蓝图拆解** · `blueprint` | 获客体系搭建、方案拆解、业务流程 | 分区开篇；无衬线；逐段推进一个可以照着理解的过程 | 编号章节；面板引述；步骤顺序突出 |
| **暖页故事** · `warm-story` | 创始人故事、客户经历、品牌成长 | 札记式开篇；衬线；宽松段落，把空间留给经历与转折 | 下划线章节；放大引句；不过度切碎故事 |
| **赤陶观点** · `terracotta-opinion` | 争议分析、经营误区、观点型获客文章 | 侧向色带；无衬线；结论与证据交替展开 | 左轨章节；括形引述；明确区分原话与作者判断 |

| **溪流问答** · `stream-qa` | 购买顾虑、服务常见问题、专业答疑 | 分区开篇；无衬线；问题与解释成组出现 | 标签章节；双线引述；适合把一个问题回答完整 |

| **工尺方案** · `workshop-plan` | 团队分工、矩阵运营、项目执行 | 报头开篇；无衬线；较高信息密度，便于查找责任和动作 | 左轨章节；证据面板；不把每个段落做成卡片 |
| **莓色洞察** · `berry-insight` | 人群心理、内容规律、反常识发现 | 窄色带；无衬线；宽松间距，在观察与解释间形成停顿 | 下划线章节；放大引句；一句发现后接具体依据 |
| **松野清单** · `pine-checklist` | 选品检查、避坑要点、发布前检查 | 横带开篇；无衬线；短节奏、易扫描，清单内容保留完整 | 标签章节；括形引述；不只靠颜色表达是否合格 |
| **远声对谈** · `echo-dialogue` | 专家访谈、客户对话、团队经验 | 札记式开篇；衬线；宽松留白，保留不同说话人的语气 | 章印标题；双线引述；用姓名或角色文字区分声音 |

这些主题在封面构图、标题组织、引用形式、字体取向和段落密度上组合成不同的阅读体验。不存在“任何文章只换一个颜色就算换主题”的设计规则。也不为每个细分行业另建一套视觉模板。

## 怎样选主题

1. **用户指定主题**：按其指定的名称或 ID 使用。用户只说“更克制”“有故事感”“像一份执行方案”，将偏好映射到主题，不要求用户先学会主题参数。
2. **用户没有指定**：根据文章的主要任务直接选择，并在交付说明中用一句话解释理由。选择主题本身不构成等待确认的门槛。
3. **混合内容**：按整篇最重要的阅读任务选择一个主题。方案中含一个故事，仍可用蓝图拆解；故事中含几条建议，仍可用暖页故事。不要在一篇文章中每节换主题。
4. **没有明显类型**：使用默认的渡鸦简报。用户反馈偏好后再调整，不预先给出十二道选择题。
5. **用户要求个性化**：先调整当前主题的允许参数，再决定是否需要新主题。不能为了“品牌色一致”把文字改成难以辨认的浅色。

### 常见需求直接对应

- “先把这篇获客文章排得清晰、专业”：渡鸦简报。
- “这篇讲从定位到内容体系的完整方法”：蓝图拆解。
- “这是真实客户从犹豫到做决定的经历”：暖页故事。
- “我要讲清一个行业里大家都理解错的问题”：赤陶观点。
- “读者看完就能按步骤完成操作”：琥珀步骤。
- “客户反复问这些问题，整理成一篇解释”：溪流问答。
- “介绍我们的做事标准与服务主张”：深港品牌。
- “这篇要给团队直接拿去分工执行”：工尺方案。
- “从几段真实咨询中提炼一个新的需求洞察”：莓色洞察。
- “读者要拿着文章逐项检查”：松野清单。
- “这是一段两个人的访谈或对话”：远声对谈。
- “文章比较长，但要保留完整的分析与依据”：墨页长读。

不要因为“做获客”就一律选强对比观点风，也不要把高客单等同于大面积黑金装饰。判断的是阅读任务和品牌表达，不是用主题暗示不存在的专业背书。

## 参数边界

配置字段有明确分工：

- `cover` 控制文章开篇的组织方式，`align` 用于封面或标题区取向。**长段正文始终左对齐**；深港品牌的居中不能扩散到整篇正文。
- `heading` 控制章节样式；`numbering` 表示是否需要顺序编号。只排版时，已有有序标题要避免双重编号。
- `quote` 控制真实引用或原文已有重点段的呈现。不能为了填满漂亮组件而编造客户评价或名人说法；普通作者判断也不能被伪装成外部引语。
- `density` 控制留白与间距的相对关系。紧凑适合查找信息，宽松适合叙事与长读；所有主题仍以手机端正文可读为前提。
- `font` 区分无衬线与衬线倾向，依靠本地中文字体回退。**不依赖外部字体下载**，不同设备字体的具体字形可能不同。
- `radius` 只修饰已有容器。不要把每段正文都包进圆角卡片。
- 颜色中 `ink` 用于正文，`muted` 用于辅助文字，`accent` 用于强调，`paper` 为背景，`tint` 为浅底区域，`line` 为装饰分隔，`highlight` 为局部高亮底色。正文与信息不能只靠细线或颜色差别区分。

## 可读性与公众号适配

- 主题以移动端单列阅读为前提。开篇的“分区”只是标题区的视觉组织，不产生需要横向滚动的正文。
- 优先保证标题、正文、列表、图注的层级；一段文字不要同时叠加粗体、强调色、底色和引述边框。
- 标题与小标题允许自然换行；不插入人为全角空格对齐文字。不通过缩小字体挤下长标题。
- 长列表适当分组；宽表格使用可读性优先的处理。版式不应掩盖缺失内容。
- 图片保留原有含义和说明。没有图片时，靠文字层级完成排版，不生成假的案例截图。
- 公众号编辑器可能过滤部分样式。以文章 HTML 中真实可用的结构与内联样式为准，主题名和颜色搭配不等于经过发布验证。
- 预览检查至少包括手机宽度下的长标题、长引用、有序列表、图片和段落间距。不能只看一屏封面。

## 对比度检查

使用 [WCAG 相对亮度与对比度定义](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)对十二套静态颜色配置进行计算：sRGB 先线性化，再按 `0.2126R + 0.7152G + 0.0722B` 求相对亮度，对比度为 `(较亮 + 0.05) / (较暗 + 0.05)`。

| 检查项 | 最低要求 | 当前十二主题中的最低值 |
| --- | --- | --- |
| 正文 `ink / paper` | 7:1 | 13.19:1 |
| 辅助文字 `muted / paper` | 4.5:1 | 5.55:1 |
| 强调文字 `accent / paper` | 4.5:1 | 6.45:1 |
| 浅底强调 `accent / tint` | 4.5:1 | 5.72:1 |

这是颜色配置的静态可读性检查，不能代替在实际手机和公众号编辑器中检查字重、字号、间距与样式兼容性。修改颜色后应重新计算；`line` 只作装饰分隔，不用于承载关键文字。
