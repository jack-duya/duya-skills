# 公众号排版执行规范

本规范供公众号能力按需读取。它把已有文章转换为适合复制到公众号编辑器的 HTML，并提供预览与检查；不接管商业判断，不默认重写文章。主题定义见[主题选择指南](wechat-themes.md)和[主题资产](../assets/wechat/themes.json)，渲染工具为 [wechat_layout.py](../tools/wechat_layout.py)。

## 1. 从当前请求直接开始

| 请求 | 应做 | 不应顺带做 |
|---|---|---|
| 只排版 | 保留正文，映射已有结构，选主题，生成文件 | 润色句子、添加 CTA、补摘要、给作者起名 |
| 写完并排版 | 先完成正文，再用同一稿生成排版文件 | 排版阶段重新写出另一版事实或案例 |
| 只改样式 | 修改主题或指定视觉部分，重新生成 | 更改标题文字、文章顺序或报价 |
| 改稿并排版 | 在用户授权范围内完成改稿，保存正文，再生成文件 | 把编造案例混入原文，省略实质修改说明 |

用户已有主题偏好就沿用；指定主题就直接用；没有指定时，根据文章题材选一套并执行，不先发 12 道选择题。不能确定细分风格时使用 `raven-brief`。交付一句选用理由即可，用户可以随时换主题。

只给了“帮我排版”而没有任何正文时，需要取得文章内容；有正文后，不为排版额外索取客户画像、产品价格、线索数据或商业档案。

## 2. 输入准备与内容保护

### Markdown 与纯文本

工具直接读取 UTF-8 文本文件。优先使用用户原有 Markdown；纯文本保存成 `.md` 或 `.txt` 输入，保留段落顺序。不要把一句看起来像标题的话擅自升级成标题，也不要替用户补目录、章节编号、引语出处、图片说明、作者签名或结尾。

工具处理以下明确的 Markdown 子集，不声称完整兼容 CommonMark 或所有扩展语法：

| 结构 | 支持的输入形式 |
|---|---|
| 标题与正文 | `#` 至 `######` 标题、普通段落 |
| 行内语义 | `**粗体**`、`*斜体*`、`~~删除线~~`、`==高亮==`、`++下划线++`、行内代码 |
| 引用与列表 | `>` 引用；有序、无序列表；缩进列表保留视觉层级 |
| 代码与分隔线 | 三个反引号围栏代码；常见 Markdown 分隔线 |
| 表格 | 简单管道表格；复杂跨行、合并单元格不在直接支持范围 |
| 图片与链接 | Markdown 图片 URL 或本地图片；Markdown HTTPS 链接 |

复杂嵌套、脚注、公式、特殊插件语法等先由宿主归一化，并保留转换稿供核对。内嵌 HTML 作为文字展示，不作为可信组件执行；不依靠 HTML 标签绕过输入边界。不能悄悄丢弃未支持内容后声称完成。

### Word、PDF、网页富文本

先用当前宿主可用的读取能力提取为可核对的文本或 Markdown。保留原文件，检查表格行列、图片位置、引号、作者和价格。PDF 扫描页需要实际 OCR 或图像阅读；没有相应能力就明确说明，不能凭文件名补写。提取没有实质问题时继续排版，不机械增加确认环节；遇到会改变原意的识别歧义时才需要补充材料或确认。

### 不变项

- 原文的事实、数字、单位、报价、产品承诺、作者和引用保持原样。
- 段落、列表顺序、表格中的对应关系保持；不能为了适应卡片而缩写原文。
- 标点不批量替换；英文、网址、代码和引用中的符号保留原意。
- 原有加粗、斜体、删除线等按原语义呈现，不把删除线解释成重点高亮。
- 原文没有的标题、摘要、作者信息、图片说明、互动与购买引导不自动生成。
- 远程图片 URL 与链接依照输入使用。本地图片经格式检查后复制到输出资源目录；在实际公众号编辑器中可能仍需重新上传。工具不保证远程资源始终可用。

排版可以改变字体、间距、颜色、边框和结构元素的视觉表现。装饰不能新增有业务含义的文字。用户授权润色时，将内容改稿与排版稿分开保存，便于核对。

## 3. 主题选择与组件组织

从[主题选择指南](wechat-themes.md)选主题。12 套主题共用一套正文语义解析与渲染机制，各有阅读节奏和组件表现；不能把 12 个主题写成 12 个独立 Skill，也不为每个行业复制一套文章逻辑。

一篇文章使用一套主题。标题、引用、列表、图片、表格、代码、分隔线应按原文结构进入相应组件，不能为了用满组件而把普通段落变成引用或添加“核心结论”卡片。已有重点保留，新增重点只在用户要求时处理。

部分主题会为二级标题增加视觉序号，依主题的 `numbering` 配置执行；原 H2 已有编号时不重复增加。视觉序号不改写标题正文，也不调整章节顺序。用户要求无编号或严格保留原有视觉结构时，在生成命令中加 `--no-numbering`；此参数关闭主题新增的编号，不删除原文已有编号。

主题参数以 `assets/wechat/themes.json` 为准；文档只描述选择条件，不再手工抄一套颜色和间距。更改主题后重跑工具，避免人工替换部分颜色造成组件不一致。

## 4. 生成文件

需要 Python 3.10+，以及当前宿主对输入和输出目录的文件读写能力。脚本只使用 Python 标准库，无须安装额外排版依赖。以下 `<duya目录>` 指包含本 Skill 的 `SKILL.md`、`tools`、`assets` 的目录，不能把仓库根目录误认为脚本目录。

列出主题：

```bash
python -B -X utf8 "<duya目录>/tools/wechat_layout.py" themes
```

生成排版，使用实际输入和输出路径：

```bash
python -B -X utf8 "<duya目录>/tools/wechat_layout.py" render --input "article.md" --output-dir "output" --theme raven-brief
```

禁止主题新增编号时，使用：

```bash
python -B -X utf8 "<duya目录>/tools/wechat_layout.py" render --input "article.md" --output-dir "output" --theme blueprint --no-numbering
```

仅在用户提供或本次写作明确确定这些信息时，才使用可选的 `--title`、`--author`、`--summary` 参数。`--title` 属于显式的标题选择，不能未经用户要求覆盖原文 H1。不要重复展示原文已有的同一标题，也不要自动把正文第一段变成新摘要。工具提供参数不代表每篇文章必须填满。

以输入 `article.md` 和主题 `raven-brief` 为例，生成：

| 文件 | 用途 |
|---|---|
| `article.raven-brief.html` | 干净正文片段，样式内联，用于正文检查与兜底 |
| `article.raven-brief.preview.html` | 浏览器预览和复制入口；工具栏属于外壳，不进入复制内容 |
| `article.raven-brief.report.json` | 本次生成的检查结果与警告；用于定位遗漏、不支持内容或潜在兼容问题 |

报告包含 `ok`、`errors`、`warnings`、`theme`、`title`、`stats`、`source_sha256`、`output_sha256` 与 `content_check`。哈希标识实际输入与输出文件的字节；`content_check` 只检查解析后的文字块是否按顺序出现在正文中，不能发现解析器自身对原文的所有误读，也不能证明全文事实或语义正确。仍需对照原稿检查数字、特殊符号和复杂 Markdown。使用本地图片时还会生成相应资源文件，交付或移动预览时需要一并保留。

重新检查正文 HTML：

```bash
python -B -X utf8 "<duya目录>/tools/wechat_layout.py" validate "output/article.raven-brief.html"
```

需要比较全部主题时生成同文对照：

```bash
python -B -X utf8 "<duya目录>/tools/wechat_layout.py" gallery --input "sample.md" --output-dir "gallery"
```

从 `gallery/index.html` 打开对照入口。每套主题各有正文、预览和报告；这是选风格的辅助方式，普通排版不需要每次生成 12 份。

## 5. HTML 与检查边界

正文 HTML 与预览外壳分开：正文采用内联样式，不含脚本、外部样式表、交互按钮或页面控制逻辑；预览页可以有自己的 CSS 和复制脚本。不能将完整预览页的 HTML 当作公众号正文，也不能复制整个页面连同工具栏一起粘贴。

不要依赖浏览器复杂布局、远程字体或脚本效果承载文章信息。图片需要自适应正文宽度；长链接、代码和宽表格需要检查窄屏效果。图片资源若是本地路径或打不开的远程地址，应明确说明实际公众号里可能需要重新上传，不能把预览中可见等同于平台可用。

生成后检查以下项目：

1. 工具是否成功生成三个文件，报告是否存在错误或警告。
2. 正文与输入是否有遗漏、重复、截断和顺序变化，标题/作者参数是否造成重复。
3. 报价、数字、链接、代码、引用、表格对应关系是否保留。
4. 浏览器窄屏预览是否读得清，是否有横向溢出、图片变形或强调过多。
5. 复制范围是否只包含正文；用户是否有可访问的预览文件和 HTML 文件。

有错误先处理再交付。警告按实际影响解释：能修复就修复；必须保留的输入或尚待平台确认的情况如实说明，不为“警告清零”擅自改正文。静态检查只检查脚本覆盖的条件，不能证明全文事实正确、所有样式都被公众号支持、外链和远程图片都可发布。

## 6. 给用户的交付与使用方式

默认交付预览页链接，附干净正文 HTML 和简短检查结果；有必要时附报告。描述实际状态，例如“已生成并通过静态检查；浏览器预览已查看；公众号编辑器尚未实测”。没有查看浏览器或实际平台就不说已经查看。

用户打开预览页后，点击复制按钮，再到公众号编辑器粘贴。若浏览器不允许自动写入剪贴板，预览页应选中正文供用户按 `Ctrl+C` 或 `⌘C` 复制；若仍未选中，请在预览里只选正文手动复制。不要引导用户复制源码中的 HTML 字符串。

粘贴后在实际公众号编辑器和手机预览中检查标题、段落、图片、表格、链接与代码。发现样式变化时按实际变化调整对应组件，不承诺“永不掉样式”。排版与复制不包含发布文章，除非用户另有明确发布请求和相应平台操作能力。

## 7. 常见失败的处理

| 现象 | 下一步 |
|---|---|
| 找不到脚本或主题 | 定位实际安装的 `duya` 目录，确认更新包含 `tools` 与 `assets`；不要只复制 `SKILL.md` |
| Python 不可用 | 使用宿主已有 Python；仍不可用时交正文和明确待执行命令，说明排版尚未运行 |
| 输入无法读取 | 核对路径、权限和编码；不从文件名猜正文 |
| Word/PDF 提取错乱 | 修复可核对的转换稿；无法确认关键内容时针对性请用户补充 |
| 报告提示未支持结构 | 对照原文检查显示；需要归一化时保持语义并保留转换记录 |
| 复制按钮不可用 | 选中正文手动复制；不要把预览工具栏一并复制 |
| 公众号图片缺失或表格变化 | 在实际编辑器重新处理对应资源或结构，再检查手机预览 |
| 用户觉得主题过重 | 换克制的主题或调整用户指定样式；不靠删正文换留白 |
