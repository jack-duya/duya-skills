# 长期记忆：真正保存、相关恢复、允许纠正

记忆帮助下次少重复背景、保留用户取舍、继续作品和方法。它不要求发布登记、客户追踪、固定复盘或完成作业，也不会自动训练模型。只有写入持久文件并再次读出，才可以说跨会话保存。

## 保存到哪里

[memory.py](../tools/memory.py) 默认保存到当前系统用户的 `~/.duya/memory/<项目别名>/records.json`。可用 `DUYA_MEMORY_HOME` 或命令 `--root` 指定其他持久目录。位置独立于源码、安装缓存与更新包。脚本会拒绝把根目录设在当前 duya 技能目录内部。

项目别名用可读的字母、数字、中文、下划线或连字符；稳定沿用，不能用斜杠、`..` 或客户敏感标识。项目已知时直接用已有别名；未确定是哪门业务时不要猜着读另一个项目。新项目首次确实需要持久保存时，按已明确业务设置简短别名，并在保存回执带上位置，方便之后使用。只有“继续上次”又没有可识别项目时，才简短确认对象。

默认不跨项目搜索。用户确认的通用个人偏好可单独放 `duya-profile`，只有明确与当前用户有关时读取；不要把某客户的定价和素材放进通用偏好。

## 什么值得记

| kind | 适合保存的内容 | 常用 status |
|---|---|---|
| fact | 用户确认的服务、范围、产品、人手、真实素材限制 | confirmed；待核实用 hypothesis |
| decision | 采用或否决的方向、原因、改变它的条件 | adopted / rejected |
| preference | 明确的语气、制作形式、协作偏好 | confirmed |
| content | 关键成稿、源模板和素材位置、已确定版本的改动说明 | draft / adopted |
| method | 新课程提炼的方法、支持/反例、条件、来源和修正 | candidate / adopted / retired |

不用保存所有聊天。即时猜测不要自动写成事实；通用方法不要自动升级为已验证规律。用户明确说“记住”要执行，未要求逐轮回执时只有重要保存或修正才简短告知。明确说本轮不保存就不写。

长文章和大材料保存为用户指定项目文件，记录摘要与路径；不要把全部媒体塞 JSON。客户隐私仅保存当前工作必要部分；记录也不是已加密保险箱。没有必要的敏感信息不复制。

## 课程知识与 Obsidian

用户要长期阅读的课程笔记、方法正文、案例和来源索引，可以保存为普通 Markdown，或放入其已明确选择的 Obsidian 知识库。具体见 [Obsidian 保存与检索](obsidian.md)。不需要把每篇正文再复制进本工具；项目记忆只按需要记录库位置、入口与重要取舍。

Obsidian 是可选载体，个人项目记忆不随之迁移。用户没装 Obsidian，仍能正常读写 Markdown；用户说“以后沿用这个方法”时，应实际读取对应笔记，而不是把“已写入知识库”说成模型已经永久学会。删除记忆中的位置记录不会删除知识库中的笔记，不能混淆两种操作。

## 使用流程与真实命令

命令中的 `<duya目录>` 是包含 `SKILL.md` 的实际绝对目录。替换目录、项目和记录编号后执行；路径有空格时保留引号。所有全局参数在子命令前。优先将数据写为 UTF-8 JSON 临时文件再 `--input` 读取，避免 shell 引号改变正文；临时输入用完清理到具体文件，记忆本体保留。

```text
python -B -X utf8 "<duya目录>/tools/memory.py" --project 装修甲 info
python -B -X utf8 "<duya目录>/tools/memory.py" --project 装修甲 search --query 出镜
python -B -X utf8 "<duya目录>/tools/memory.py" --project 装修甲 get --id <返回的id>
python -B -X utf8 "<duya目录>/tools/memory.py" --project 装修甲 put --input <临时记录.json>
python -B -X utf8 "<duya目录>/tools/memory.py" --project 装修甲 update --id <id> --expect-revision 1 --input <修正.json>
python -B -X utf8 "<duya目录>/tools/memory.py" --project 装修甲 forget --id <id> --expect-revision 2
```

新建记录例（示意，不要写入真实客户项目）：

```json
{
  "key": "owner-on-camera",
  "kind": "preference",
  "status": "confirmed",
  "title": "老板只接受短出镜和现场旁白",
  "body": "用户明确不做长时间正脸口播。采用现场动作配旁白；必要的判断由老板用一句话说明。并非完全禁止出镜。",
  "sources": ["用户在本次对话明确确认；按实际情况填写日期或可用会话位置"],
  "tags": ["出镜", "制作条件"]
}
```

`key` 可选但建议给长期固定事实使用。新建 `put` 默认期待不存在（revision 0），同 key 已存在则报冲突，防止静默覆盖。要完整替换已有 key，先 `get` 最新版本，再 `put --expect-revision N`，输入包含整条所需字段。局部修正用 `update`，只给改变字段并提供实际 revision。

`search` 是空格分词后的子串交集检索，**不是语义向量搜索**。中文用短词，例如“出镜”或“装修 老板”；没搜到时改词/标签，或无 query 查看项目最近记录，再 `get` 完整内容。空目录读取不会创建空项目。一次不需要读全部历史。

## 冲突、删除与恢复

- 新消息纠正旧事实：读取当前版本，更新正文、来源和状态，后续以最新为准。不是另存一条相反事实让两个记录竞争。
- 用户否决方向：更新决策与原因，别下次再当推荐首选。其他适用条件变化时可以解释后重新讨论。
- 用户说忘记：找到确切记录后 `forget`，成功才说删除。脚本不保留删除历史；此前导出的副本或宿主聊天不在它的删除范围。
- revision 冲突：另一个写入已发生，重新读再判断；不能强行改成猜测的版本号。
- 写锁 busy：等待正在进行的同项目写入结束再重试；不要删除活跃锁。进程异常遗留锁时，先核 PID 确已结束，再清理该明确锁文件。
- 旧/损坏格式：脚本拒绝覆盖；先检查具体文件，用户有既有记忆需要迁移时保留原文件再转换，不能自动清空重建。

写入使用同目录临时文件与原子替换，项目有独占写锁。主 Agent 统一写入，子 Agent 回传待保存信息。脚本保存结构、隔离项目、防止覆盖，不会判断真假、自动归因或自动把方法改得更正确。

没有 Python/文件权限时，完成当前答复并明确“此环境未持久保存”，可交付一段可保存摘要；不能说“以后我会自动记住”。
