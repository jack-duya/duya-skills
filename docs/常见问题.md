# 常见问题

[返回首页](../README.md) · [新手入门](新手入门.md) · [安装指南](安装指南.md)

## 渡鸦到底是一个软件，还是一套提示词

渡鸦是一套给 AI 客户端使用的 Skills。它包含一个主入口、12 个内部能力包、详细知识库和配套工具。客户端提供模型和执行能力，渡鸦提供商业判断、获客方法、内容创作与组织协作的方法。

你不需要运行一个新的后台系统。装进支持 Skills 的客户端后，直接用对话提出问题即可。

## 为什么全目录有 12 个能力，安装时只显示一个 duya

这是预期设计。`duya` 是你使用的入口，其他能力由它根据本轮需求读取和组合。

你问“这条开头怎么改”，它应直接改开头；你问“我该不该招五个剪辑”，它才需要结合获客打法、素材条件和团队分工判断。无需你记住 12 个命令。

## 我必须先学习商业理论、填写业务表格吗

不用。直接给你已有的信息就可以：你卖什么、谁在买、目前想做什么、哪里卡住。已经聊过的背景应沿用；没有的数据就没有，不要求你先补全客户台账、发布记录或经营报表。

只有缺失信息会改变选择时，它才应追问。比如同样是“起号”，卖本地到店服务和全国线上服务，优先的平台与表达方式可能不同。

## 会不会每个问题都先做一遍商业诊断

不应该。确定目标下的标题修改、局部改写、读取模板，直接完成就好。

“账号不够，去哪里买”这类把解决办法当成问题的请求，才需要先看真实目的和限制：到底是需要覆盖更多客户、缺少有效内容，还是一条已经跑通的获客路径确实需要扩大分发。重新定义问题是为了给对解法，不能变成固定长问卷。

## npx、node 提示不是内部或外部命令

先按 [安装指南](安装指南.md)安装 Node.js LTS，然后关闭并重新打开终端，再检查 `node --version` 和 `npx --version`。

Windows 如果提示无法运行 `npx.ps1`，可以在同一命令中把 `npx` 换成 `npx.cmd`，例如：

```powershell
npx.cmd -y skills add jack-duya/duya-skills -g --skill duya --agent codex
```

不需要为了安装渡鸦而把系统的脚本执行策略永久调低。

## 下载失败、找不到仓库或提示 Git 错误

先确认浏览器能打开 [jack-duya/duya-skills](https://github.com/jack-duya/duya-skills)，再检查终端能否运行 `git --version`。

网络超时就换一个可访问 GitHub 的网络后重试；终端提示缺少 Git 就先安装 Git。也可以下载 ZIP，按 [手动安装](安装指南.md#方式三手动安装)复制整个 `skills/duya` 目录。

不要在报错截图里公开访问令牌、个人配置或客户材料。

## 安装成功了，AI 为什么找不到 duya

按这个顺序检查：

1. **客户端是否选对。**装给 Claude Code 的技能不代表同一台电脑上的其他应用都能看见。
2. **范围是否选对。**带 `-g` 是当前用户安装；不带 `-g` 通常跟当前项目有关。
3. **文件是否完整。**目标目录应直接有 `duya/SKILL.md`，还要有 `internal`、`knowledge`、`references`、`tools` 和 `assets`。0.3.0 的公众号主题与排版工具也在这个完整目录中。
4. **是否开了新对话。**已有对话可能仍在使用安装前的上下文。
5. **是否重复装了多个版本。**旧插件、手动复制和通用安装可能同时存在，先核对本轮实际读取的是哪份。

可以运行 `npx -y skills list -g` 查看全局安装记录，也可以让 AI 展示它找到的 `duya` 主文件路径。

## 到底输入 $duya 还是 /duya

取决于客户端和安装方式。

| 环境 | 本仓库通用安装后的用法 |
|---|---|
| Codex | `$duya` 加你的问题 |
| Claude Code 独立 Skill | `/duya` 加你的问题 |
| Claude Code 本仓库插件 | `/duya:duya` 加你的问题 |
| Cursor 及其他支持 Skills 的客户端 | 自然语言“使用 duya”，或从客户端技能选择器选择 |

Claude Code 的插件命令带插件命名空间，因此本仓库插件用 `/duya:duya`。不要在所有客户端里照搬同一个符号。后续同一段任务可以自然对话，不用每句话都重新输入入口。

## 可以用豆包、普通 ChatGPT 网页、WorkBuddy 或手机端吗

要看它具体支持什么。能够聊天不代表能够加载完整 Skills、读取知识文件、连接 MCP 或保存本地记忆。

如果客户端提供“导入 Skills”功能，先导入完整目录，再分别验证文件读取、模板检索和记忆保存。没有这些能力时，可以提供必要资料体验部分对话能力，但不能把粘贴主提示词说成完整安装。本项目没有对这些环境逐一完成全功能实测。

## 装好了 duya，为什么没有自动出现模板库

Skill 和 MCP 是两项配置。通用安装工具负责复制技能文件，不负责把仓库根目录的 `.mcp.json` 自动注册到所有客户端。

按 [安装指南的模板库部分](安装指南.md#连接渡鸦图文模板库)手动添加 `moyaclaw-template-mcp`。如果之前通过一个包含 MCP 的插件安装，先检查是否已连接，不要重复添加同名服务。

## 模板库地址打开后显示 406

浏览器直接打开时出现 406，不能说明服务故障。这是 MCP 接口，应使用支持 **Streamable HTTP** 的 MCP 客户端连接。

连接类型选 HTTP，地址填 `http://43.242.194.25:3170/mcp`，当前不用 Token 或 Key。配置完成后实际检索一条模板，才能判断工具链路是否成功。

## MCP 一直连接不上

先检查三个具体点：

- 地址有没有多余的方括号、括号、空格，或误改了端口。
- 传输类型是否为 **Streamable HTTP / HTTP**，而不是 SSE、stdio。
- 客户端是否禁用了这个服务，或当前网络无法访问该 HTTP 地址。

再看错误是超时、连接拒绝还是配置格式错误，按实际错误处理。部分客户端或组织网络会限制远程 HTTP 服务；这时不能只改成一个服务器并未提供的 HTTPS 地址。

没有原生 MCP 但客户端能运行 Python、访问网络时，渡鸦可以尝试附带的只读脚本。工具仍不可用时，它应说明没有查到实时模板，使用你提供的样本或现有知识继续，而不是编造库内编号和检索结果。

## 模板库没有我的赛道怎么办

先换更直接的产品或服务名称检索，再找购买场景、客户顾虑和内容形式相近的赛道。

例如家政保洁可以从“服务过程怎样让人放心”“效果怎样被看见”“什么现场细节证明专业”寻找结构相近的参考。迁移的是表达机制和证据方式，产品事实、服务范围、价格和客户经历仍要来自你自己。

渡鸦应告诉你用了什么相邻赛道、哪些结构能借鉴、哪些内容需要重写；不能把不相关的高赞文案只换一个行业名。

## 为什么拿到模板了，AI 还说没有看过图片

模板接口返回图片 URL，不等于当前客户端已经读取图片。只有实际打开或查看图片后，才能分析画面和版式。

如果当前环境只能读正文，渡鸦可以分析文字结构，说明视觉部分尚未覆盖；你也可以把图片直接放进对话。不要把文本分析包装成完整的图文或视频逐帧分析。

## 我只是想写一篇文案，为什么答案还是很空

先看它有没有使用你已有的业务资料、知识库和适合的模板。有效的稿子应该能说清：哪个人、在哪个场景、为什么愿意继续看、最后获得了什么回报。只有“抓痛点、做共鸣、提高信任”还不算成稿。

你可以直接纠正：

```text
这版太空。请结合我已有业务信息重新写；先检索适合的模板或读取对应方法，再给完整成稿。不要只解释应该怎么写，也不要编造我的案例和业绩。
```

如果你只要一个开头，也可以直说“只改开头，保留正文和现有购买理由”。

## 公众号排版要另外安装一个 Skill 吗

不用。0.3.0 已把排版接入原有公众号能力，仍然通过 `duya` 提问。12 套原创主题是视觉方案，整套体系仍是 **1 个入口、12 项能力和 23 篇专业知识**。

可以直接说：

```text
$duya 这篇文章不改文字，自动选主题，输出可复制到公众号的 HTML：……
```

也可以让渡鸦写好文章后接着排版。没有风格偏好时它会根据文章选一套，不需要先挑完 12 个主题。具体步骤见[公众号排版教程](公众号排版.md)，风格可以看[在线主题画册](https://jack-duya.github.io/duya-skills/wechat-gallery/)。

## 排版需要安装什么，为什么只收到一段 HTML 代码

实际生成需要客户端能读写文件，并运行 **Python 3.10+**。内置工具只使用标准库，无须额外安装 pip 依赖。更新时要保留完整 `skills/duya` 目录，不能只复制 `SKILL.md`。

成功生成应得到三个文件：正文 `.html`、预览 `.preview.html`、检查报告 `.report.json`。只有聊天中的代码不等于已经生成并检查了这些文件。可以要求：“请运行内置排版工具，给我能打开的预览文件和检查结果。”当前环境不能执行 Python 时，它应说明排版尚未运行。

## 只排版会不会把我的文章改掉

只排版时应保留正文、事实、段落顺序、报价、引用和标点，不自动补案例、作者签名或结尾话术。需要改稿时直接说明范围，渡鸦再完成相应写作。

主题会调整字体、间距、章节和引用的视觉形式；部分主题有章节视觉序号。希望也保留原来的编号表现时，加一句“不要新增编号”。排版报告用于检查工具覆盖范围内的转换问题，不等于文章事实已经被核实。

## 怎样复制到公众号，能保证样式完全一样吗

用浏览器打开 `.preview.html`，点击页面中的复制按钮，再到公众号编辑器粘贴。不要复制源码，也不要把预览页工具栏一起选进去。浏览器不允许自动复制时，按页面提示选中正文，再用 `Ctrl+C`（Mac 为 `⌘C`）手动复制。

公众号可能调整样式，图片也可能需要重新上传。粘贴后仍要检查编辑器和手机预览中的标题、段落、图片、表格与链接。浏览器看起来正确、静态检查通过，都不代表平台粘贴已经验证。生成排版与复制正文也不会自动发布文章。

## 会自动发布、买账号、帮我投放吗

本项目主要提供判断、方案、成稿、研究和团队设计。模板 MCP 是只读工具，不负责发布和购买。

账号、广告投放、素材授权、发布工具和平台权限由你的实际业务与客户端决定。不能因为 Skill 写了一套流程，就认为已经接好了这些外部系统。

## 必须追踪每条作品和每个客户才能使用吗

不需要。你提供的咨询、作品表现或客户反馈可以帮助判断；没给就使用当前事实，说明仍需验证的部分，不要求建立 CRM、完成作业或逐条登记发布结果。

“播放很高但没人咨询”和“没有播放”是不同问题，评价也不一样。渡鸦会区分内容表现和获客目标，但不因此强制你维护一套记录系统。

## 量子阅读是不是把课程总结短一点

不止摘要。它应区分观点、证据和推断，找出适用条件与反例，解释方法怎样进入你当前的业务，再按需要保存为可继续使用的知识。

给一篇文章可以轻读，给多份课程可以比较。没有要求每次按固定阶段做作业，也不会把记下的方法自动变成已验证的科学规律。

## AI 说记住了，下次却没记住

先检查是否真的写入了持久文件。默认记忆目录是 `~/.duya/memory/<项目别名>/records.json`；客户端需要文件权限和 Python 执行能力。

还要确认是不是同一个电脑、用户和项目别名。当前版本不会自动把本地记录同步到另一台电脑或另一个云端聊天工具。

你可以说：“查看这个项目已经保存的记录，告诉我实际文件位置。”如果没有成功保存，它应如实说明；不能把当前对话仍有上下文当成跨会话记忆。

## 能修改或删除记忆吗

可以直接要求修改或忘记具体记录。成功后应能从该项目记录里核对变化。

修改技能本身或卸载技能，不等于删除个人记忆。删除某条渡鸦记忆，也不等于删除宿主聊天、之前导出的文档或你自行备份的副本。需要忘记时要说明具体范围。

## 更新会不会把我的资料覆盖掉

默认个人记忆放在 `~/.duya/memory`，与安装目录分开。成稿和业务材料也应保存到你自己的项目目录。

更新会替换安装范围内的技能文件。你如果直接改过 `SKILL.md` 或知识库，先另存自己的修改；不要把唯一一份业务材料放在插件缓存或安装目录。

## 能保证爆款、精准线索和成交吗

不能。渡鸦可以提高判断和表达的具体程度，帮助比较打法、找到内容和组织中的问题，但结果还取决于真实产品、素材、执行、平台分发和市场反馈。

模板存在、文稿通过检查、测试对话表现正常，都不等于真实获客效果已经验证。它应给有条件的判断，也应在新事实出现时修正建议。

## 发现问题怎么反馈

在仓库 [Issues](https://github.com/jack-duya/duya-skills/issues) 提交即可。最有帮助的信息是：

- 你使用的客户端和安装方式。
- 触发问题的原始提问与必要业务背景。
- 你期望什么、实际发生什么。
- 有报错时附完整错误文本，涉及客户信息时先脱敏。

如果是文案不好，给出“哪句话不对、为什么不像你的业务、你更认可哪个参考”通常比一句“没网感”更容易定位问题。无需提交整套经营数据。
