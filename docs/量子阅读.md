# 量子阅读：读懂资料，形成方法，下次继续使用

[返回首页](../README.md) · [新手入门](新手入门.md) · [使用案例](使用案例.md) · [安装指南](安装指南.md)

量子阅读帮助你把书、课程、长文和已有经验，整理成**能够解释、知道适用条件、能用于实际任务的知识**。你可以只问一段话，也可以让渡鸦读完整门课、对照旧方法、演示应用，再保存成以后能找回的笔记。

在 Codex 中使用 `$duya-learning`；也可以继续向 `$duya` 提问。Claude Code 独立安装对应 `/duya-learning`，本仓库插件对应 `/duya:duya-learning`。后面的自然语言保持不变。

**保存到 Obsidian 是可选项。**不用 Obsidian，也能完成阅读、解释、应用和普通 Markdown 文件交付。使用 Obsidian 时，渡鸦把笔记写入你选定的本地知识库，再用笔记链接连接来源、方法和应用；不需要另配 Obsidian MCP。

## 第一次用，照着这三步说

### 1. 把材料交给渡鸦

可以粘贴一段原文、附上文件，或者给出当前客户端能访问的文件地址。材料多时，直接给文件夹并说明要读哪些范围。

```text
$duya-learning 读这份课程资料：D:/课程/客户需求与内容表达.md。
我做家庭日常保洁，想弄清楚新号的内容应该怎样选择切口。
请保留课程的关键案例、条件和反例；用一个具体内容任务演示怎么应用。
这次先给我详细阅读结果，不用存入知识库。
```

把示例地址和业务换成自己的即可。已经在前文说明的业务不必重写；不需要先填客资表、提供播放后台或整理成指定问卷。

Markdown、纯文本可直接读取；PDF、Word、网页和视频取决于客户端实际提供的读取能力。只有视频转写时会分析文字，不会冒称看过镜头。整课较长时会分批处理，并说明已读与尚未覆盖的部分，不要求你每读一讲就输入“继续”。

### 2. 说明这轮想拿到什么

| 你的目的 | 直接怎么说 | 这轮应拿到什么 |
|---|---|---|
| 看懂一句话 | “这句话是什么意思，用我能理解的例子解释。” | 解释、关键区别、贴切例子 |
| 理解整门课 | “完整读一遍，保留重要论证、案例和适用条件。” | 课程主问题、方法详解、证据边界和阅读覆盖 |
| 把知识用于工作 | “用我这条旧稿演示，直接改出能用的版本。” | 对原稿的判断、具体改稿、使用条件 |
| 比较新旧经验 | “把两种说法放在相同条件下比较，再决定怎么整合。” | 真正的分歧、条件分支、该保留或修订的部分 |
| 留作长期资料 | “整理成有来源和关联的笔记，存进这个知识库。” | 实际文件、关联关系与保存位置 |

任务小就直接完成；只有整课阅读、资料比较或方法整合才需要展开。四步方法不会变成每次都必须填写的表格。

### 3. 需要保存时，选一个位置

普通文件交付可以说：

```text
把刚才的阅读结果整理成 Markdown，放在 D:/我的资料/读书笔记。
保留完整解释、来源和应用例子。
```

已经有 Obsidian 知识库时可以说：

```text
把刚才值得复用的方法存进我的 Obsidian 知识库：D:/我的知识库。
沿用现有分类；关联已经存在且真正相关的笔记。
保留来源、适用条件和反例，保存完成后告诉我文件位置。
```

这是示例路径，需换成你自己的位置。对话中已经选定知识库，渡鸦会直接使用，不再反复确认。尚未确定时，可以先只读查找候选；找到多个库时会让你选，不会按最近打开时间猜测目的地。只想看阅读结果时，完全不必先选存储工具。

## 四步方法具体在做什么

“审查、提纯、淬炼、重塑”用于保证知识以后能被正确使用。这里的“量子”沿用墨鸦原有的方法名称，不表示由量子物理支持，也不代表读完一次就训练了模型。

| 方法 | 真正在判断什么 | 以保洁内容为例 |
|---|---|---|
| 审查 | 谁说的、在什么情境说的、给了什么证据、读到了多少 | “新号先讲生活”是某种起步经验，还是所有内容都必须遵守的规则？原材料有没有实际效果证据？ |
| 提纯 | 这个观点要改变哪一个选择，怎样做才有用 | 当目标人尚未想到专业服务时，从其已有处境解释相关性；不能只保存“要共鸣”三个字 |
| 淬炼 | 换成自己的任务能否做出来，改变条件后答案会不会变 | 给第一次了解保洁的人写观看入口；再换成已经比较报价的人，检查是否应直接回答服务范围 |
| 重塑 | 与旧方法怎样连接，下次什么时候调用，哪些说法需要修订 | 保存带条件的方法，并关联原材料、保洁应用与“泛垂直/精准”辨析 |

例如，同一份资料出现“客户不了解专业问题”和“要说清服务范围”，两句话可能面向不同阶段。渡鸦应识别这个差别，再具体选表达；把它们压成“先吸引，再转化”仍不足以指导下一篇内容。

资料中的观点、你提供的业务事实、渡鸦的推断和新增应用会在关键位置分清。有案例就保留案例的起点与变化；没有效果材料，就不把方法写成“已验证获客”。详细方法来源见[量子阅读知识](../skills/duya/knowledge/learning/quantum-reading.md)。

## 六种可以直接复制的请求

### 1. 概念解释：只把这一点讲明白

```text
$duya-learning 课程说“观看理由、购买理由和满意理由要分开”。
请读这段上下文，用家庭保洁举例，解释三者分别回答什么问题。
我只需要看懂并能区分，不用读完整门课，也不用生成知识库。
原文：……
```

应得到具体区分：什么让相关的人愿意看、什么帮助其选择服务、什么是服务完成后才能判断的体验。例子必须与材料和业务条件对应，不能凭空声称某类客户已经买单。

### 2. 整课阅读：保留案例和推导，不只压缩目录

```text
$duya-learning 完整读这个文件夹里的三天课程资料：D:/课程/三天线下课。
先辨认正文、转写、补充材料和重复版本，再分批完成阅读。
讲清课程在解决什么问题、方法怎样成立、关键案例如何转折、哪些情况不能套用。
最后给完整阅读稿和覆盖说明；遇到读不了的文件，说明影响并继续处理其他材料。
```

没有实际读到的图、音频或章节应明确列出。整理稿中的编者解释和讲师原话不混为一谈；结论需要理论核实时再查一手资料，不为每个日常观点硬配理论名称。

### 3. 业务应用：读完直接改出作品

```text
$duya-learning 从这份资料中找能改善我这条短视频的方法。
我的服务是家庭日常保洁，素材只有厨房清理过程，没有客户口述。
先指出旧稿的问题，再写出完整可拍旁白，并说明什么情况下不该这样改。
不要编客户经历，也不要停在“加强共鸣、提高转化”。
资料：……
旧稿：……
```

这轮应交完整应用结果。阅读是为了完成当前改稿，不会让你先做练习、再申请调用短视频能力。

### 4. 冲突整合：先比较条件，再判断是否矛盾

```text
$duya-learning 资料 A 强调新号先用泛垂直，资料 B 强调精准客户和购买理由。
请实际读取两份材料，对照它们的对象、任务、前提和证据。
如果是不同条件下的方法，给出选择条件；如果真冲突，保留分歧并说明你当前的判断。
用“家庭保洁新号”和“客户已经在比较报价”各演示一次。
A：……
B：……
```

合格结果会把“账号新旧”“内容入口”“对象是否适配”“读者正在完成什么任务”区分开，而不是宣布泛垂直或精准永远正确。没有证据支持的数字、效果倍数和绝对承诺不会进入通用规则。

### 5. 保存到 Obsidian：保存能复用的内容和真实关联

```text
$duya-learning 把刚才采用的方法存进 Obsidian，知识库路径是 D:/我的知识库。
先看已有相关笔记，沿用我的分类，保留来源、条件、反例和本次应用。
只连接实际存在或本次已创建的相关笔记，不为凑关系图造空概念。
不要改已有配置；同名但内容不同时，保留旧文并说明如何另存新版。
```

渡鸦会检查写入结果，再给出可打开的文件位置。笔记中指向旧笔记的链接已经能形成关系，无须为了制造“双向”而逐份改写旧文。

### 6. 找回复用：下一次让知识进入工作

```text
$duya-learning 从 D:/我的知识库 找上次关于“内容入口”和“客户比较服务”的方法。
先读取对应笔记和必要来源，再判断哪一条适合本轮。
这次客户已经在问服务包含哪些区域，我要做一张下单前说明图。
用已保存的方法给完整文案；说明沿用了什么，以及这次条件有什么变化。
```

它应实际找到笔记，复核适用条件，再完成文案。没有找到就说明检索结果，不把当前临时生成的建议冒称为旧知识库内容。文件夹换位置或换电脑时，需要让当前客户端能够访问新的位置。

## 完整静态示例：保洁内容该先讲情绪，还是直接讲服务

这个例子从一份完整原料走到方法、成稿、笔记关联和下次复用。**原料由渡鸦为教学编写，属于静态演示；不是课程逐字稿、真实客户案例或经过发布验证的内容。**它用来展示交付应该具体到什么程度，不证明这些稿件能带来多少播放或咨询。

[下载可打开的示例库 ZIP](quantum-reading-example.zip) · [阅读本例完整原料](../skills/duya/assets/learning/sample-source.md) · [打开示例库目录](learning-example/) · [阅读示例索引](learning-example/渡鸦知识库/量子阅读示例索引.md)

想先看实际笔记，可以下载上面的 ZIP，解压后在 Obsidian 中打开 **`duya-quantum-reading-example` 文件夹**，再点“渡鸦知识库 → 量子阅读示例索引”。从 GitHub 网页打开 ZIP 后若没有直接下载，使用文件页的下载按钮。下面继续说明这套笔记怎样从原料形成。

### 第一步：给原料和本轮目的

原料分四段，讨论的是：

1. 对尚未寻找服务的人，具体家务处境为什么可能让其愿意继续看。
2. 继续观看与选择服务为什么需要不同信息。
3. 同一个厨房问题，怎样变成认识型和比较型两种内容。
4. 哪些方法可以暂存，哪些实际业务事实和效果仍然未知。

你可以把[原料文件](../skills/duya/assets/learning/sample-source.md)下载到本地，然后这样说：

```text
$duya-learning 读取我附上的“保洁内容该先讲情绪，还是直接讲服务”。
这是教学材料，不是真实客户结果。
请从中提炼按读者处境选择内容入口的方法，解释观看理由和购买理由的区别。
用两种读者处境各写一条完整内容，并保留不适用条件。
把来源、方法、概念、应用和待确认问题保存到我已选的 Obsidian 库，给我一个阅读入口。
```

如果本轮没有选定 Obsidian 库，可以把最后一句换成“给我普通 Markdown 笔记和一个索引，保存到我指定的文件夹”。阅读与应用任务保持相同。

### 第二步：把判断和边界做清楚

这份材料可以支持的判断是：**读者此刻在解决什么，比账号是新是旧，更直接地影响这一条内容应怎样开头。**

认识型内容可以从做完饭还要收拾厨房的处境进入；已经在搜索清洁范围的人，则应先得到范围与限制。前者解释为什么与自己有关，后者帮助做具体选择。

这里没有证据支持“新号必须先发情绪内容”“共鸣就会购买”或“表面清洁一定包含拆洗”。没有商家真实服务清单时，可以写询问范围的方法，不能替商家承诺“我们全部包含”。

四步工作在本例中的结果应当是：

| 工作 | 实际结果 |
|---|---|
| 审查 | 确认四段教学原料已处理；没有附视频、访谈或经营数据 |
| 提纯 | 从“讲情绪还是讲服务”提炼出“按读者当前任务选择入口” |
| 淬炼 | 分别写出认识型、比较型两条完整内容，再用明确询问拆洗范围的情境检验边界 |
| 重塑 | 保存来源、方法、概念、应用和问题，并说明每条关联的理由 |

### 第三步：交出完整方法笔记

这份方法应能让下一次使用者知道如何选、何时不适用。下面完整展示[示例方法笔记](learning-example/渡鸦知识库/方法-按读者处境选择内容入口.md)中的方法正文及其来源、边界和关联内容；保存文件还会带上类型等属性。

```markdown
# 方法-按读者处境选择内容入口

## 解决什么问题

避免只凭账号新旧决定所有文案都讲情绪或都讲干货。

## 核心判断

先看读者此刻在解决什么，再确定本条负责让人意识到有关、理解问题，还是比较服务。

## 怎样做

- 读者尚无服务需求概念：选一个同类人的具体处境，让他看到与自己有关；之后连接到可解释的任务。
- 读者已在搜索范围或报价：先回答对应问题，保留限制，别用长故事拖延。
- 商家信息不足：完成内容方向和结构，商家的承诺等真实资料明确后再写。

## 改变条件后怎样改答案

如果输入从“新号认识型内容”变成“回复一个正在问拆洗范围的客户”，就直接回答拆洗范围，不再推荐一段情绪化开头。

## 来源

保洁内容教学材料：第一、第二、第三段；本条步骤为教学整合。

## 适用边界

- 泛入口仍须与同类客户的需求相关，不等于追无关社会热点。
- 本方法是静态整合，尚无效果验证。

## 关联依据

- [[渡鸦知识库/来源-保洁内容教学材料|来源-保洁内容教学材料]]：可回查原文和材料身份。
- [[渡鸦知识库/概念-观看理由与购买理由|概念-观看理由与购买理由]]：选择入口后，还需区分本条在解决观看还是购买判断。
- [[渡鸦知识库/应用-同一个厨房问题的两种写法|应用-同一个厨房问题的两种写法]]：两条具体内容展示同一方法在不同读者意图下的应用。
```

它保留了一个能改变动作的分支：读者已经在问范围时，直接答范围。这样的边界比“内容要有共鸣”更能帮助下一次写作。

### 第四步：给出两种完整应用

下面两条就是[示例应用笔记](learning-example/渡鸦知识库/应用-同一个厨房问题的两种写法.md)中的静态成稿。两条都不替某家店编服务能力、报价或用户反馈。

**认识型内容：做完饭，厨房好像还没下班**

> 菜端上桌了，灶台上还有油点；刚擦完台面，水槽里的碗又堆起来。
>
> 有时候让人累的不是哪一块特别脏，是厨房的活儿总没有一个明确的结束。
>
> 如果你想找人帮忙，先别只问“打扫一次多少钱”。把最想交出去的事列出来：台面去油、灶台表面清洁，还是需要另行确认的拆洗。任务说清楚，才好判断哪种帮助适合你。

**比较型内容：厨房保洁前，先把这三件事问清**

> 第一，本次包含哪些位置？让对方把范围说具体，不要只听“整个厨房”。
>
> 第二，哪些项目涉及拆洗，需要另行确认？表面清洁和拆开处理，不能只凭名称当作同一件事。
>
> 第三，额外项目怎样计费？先核对，再决定是否需要。
>
> 同样写着“厨房保洁”，范围可能不一样。先把需求和项目对上，比较价格才有意义。

第一条从具体家务处境进入，再帮助读者拆清想交出去的任务；第二条直接帮助已经在比较的人询问范围。换了读者任务，表达顺序就改变了。是否用于某家店的正式内容，仍需结合其真实服务和素材调整。

### 第五步：保存五篇笔记和一个索引

本例只保存足够解释与复用的内容，目录是：

```text
learning-example/
└── 渡鸦知识库/
    ├── 量子阅读示例索引.md
    ├── 来源-保洁内容教学材料.md
    ├── 方法-按读者处境选择内容入口.md
    ├── 概念-观看理由与购买理由.md
    ├── 应用-同一个厨房问题的两种写法.md
    └── 问题-哪些信息会改变这次建议.md
```

示例库根目录另有 `README.md` 和 `原始教学材料.md`，便于说明打开方法和回查原料。从[索引](learning-example/渡鸦知识库/量子阅读示例索引.md)进入后，可以按“来源 → 方法 → 概念 → 应用 → 待确认问题”阅读，也可以从当前问题直接找到对应方法。

关联要有理由。例如，方法连接概念，是因为下一步需分清观看与购买判断；应用连接待确认问题，是因为商家的服务范围会影响实际文案。**连线来自笔记内的链接，不会自动证明两种观点有因果关系。**

笔记分类和数量只是这个小例子的选择。你已有成熟知识库时沿用原结构；只读一个概念时可能只需要一篇笔记，不要求每次都建立六个文件。

### 第六步：下次找到它，再处理一个新问题

下一次不需要重新发送整份原料。让渡鸦在你实际保存的库中找方法，并提供本轮的新事实：

```text
$duya-learning 从 D:/我的知识库 找“按读者处境选择内容入口”和“观看理由与购买理由”。
实际读取笔记，再根据下面这份教学用服务清单写一条咨询回复。
服务清单：包含灶台表面、台面清洁；不包含油烟机拆洗。
客户问：“油烟机拆洗包不包含？”
直接给回复，再用一句话说明为什么这次不先讲家务情绪。
```

**这里的服务清单和客户提问也是教学假设。**真实使用时用你的实际清单和原话替换；原料没有提供这家店的范围，因此不能把本轮新信息倒写成原课程事实。

依据这组明确输入，回复可以是：

> 这项服务包含灶台表面和台面清洁，不包含油烟机拆洗。如果你主要想处理油烟机内部，这项服务不能覆盖，需要先找能提供对应拆洗的服务，再确认范围。

理由很具体：对方已经提出范围问题，当前需要确认服务是否适配；继续讲“我懂你的累”没有回答这个问题。此次实际检索应指向方法和概念笔记，再使用新清单完成回复，不能只说“根据我学到的知识”。

## 存进 Obsidian 后怎么看

### 打开你选定的文件夹

Obsidian 的知识库（vault）本质上是本地文件夹。已经有库，就让渡鸦把笔记写入你选定的库；还没有库，也可以先接收 Markdown 文件，再把它所在的文件夹打开为知识库。[Obsidian 官方：管理知识库](https://help.obsidian.md/manage-vaults)

在 Obsidian 中打开左下角的知识库切换入口，进入 **Manage Vaults…**，找到 **Open folder as vault**，点击 **Open**，选择存放笔记的文件夹。中文界面名称可能显示为“管理仓库”“打开文件夹作为仓库”。打开后先从文件列表找到本次入口笔记或方法笔记。[操作依据](https://help.obsidian.md/manage-vaults)

使用下面的示例库时，应选示例库的整个文件夹；不要把整个 Skills 安装目录当作自己的笔记库。Obsidian 自己可能建立配置目录，渡鸦的笔记保存不需要替你修改 `.obsidian`。

### 用本教程的示例库试一遍

1. 下载 [量子阅读示例库 ZIP](quantum-reading-example.zip)并解压。
2. 在 Obsidian 的 **Open folder as vault** 中选择解压出来的 **`duya-quantum-reading-example`**。这个根目录内应同时看见 `README.md`、`原始教学材料.md` 和 `渡鸦知识库` 文件夹。
3. 在左侧文件列表打开 **渡鸦知识库 → 量子阅读示例索引**，先读索引，再依次打开来源、方法和应用。
4. 在方法笔记里点击“来源”和“应用”的关联，核对它们能打开对应文件，再按下一节查看关系图。

如果你下载的是**整个 GitHub 项目源码**，同一份示例位于 `docs/learning-example`，应把 **`learning-example`** 打开为知识库。ZIP 根目录和源码中的这个目录内容对应，只是文件夹名称不同。两种方式都不要只打开里面的 `渡鸦知识库` 子文件夹，否则带 `渡鸦知识库/` 前缀的库内链接会指向错误位置。

不用 Obsidian 时，解压后用任意 Markdown 阅读器打开文件即可。若阅读器不识别双链，仍可按文件名打开相应来源、方法和应用，正文内容不依赖图谱显示。

### 先点开笔记，再看关系

本次保存使用库内链接连接笔记，例如：

```text
[[渡鸦知识库/方法-按读者处境选择内容入口]]
```

点击后应打开对应方法。文件夹路径从库的根目录开始，Windows 下也使用 `/`。Obsidian 同时支持这种双链写法和标准 Markdown 链接；教程示例使用双链方便在库内导航。[Obsidian 官方：内部链接](https://help.obsidian.md/links)

**全局关系图：**点击侧边工具栏的 **Open graph view**。节点表示笔记，连线表示笔记之间的内部链接；点击节点可以打开笔记。它展示的是文件关系，不能单凭节点多或连线密判断知识质量。[Obsidian 官方：关系图](https://help.obsidian.md/plugins/graph)

**局部关系图：**先打开一篇方法笔记，再从命令面板运行 **Open local graph**。它只看当前笔记附近的关联，可以调整深度。阅读一个方法时，局部图更适合检查“来源在哪里、应用在哪里、边界在哪里”。[操作依据](https://help.obsidian.md/plugins/graph)

如果图里出现没有实际文件的链接，先核对笔记名与路径；也可以在关系图过滤器中打开 **Existing files only**，只显示已存在文件。新库只有几篇笔记时，图自然很小，不需要为了像大库而补一堆空笔记。[过滤器说明](https://help.obsidian.md/plugins/graph)

## 保存、记忆与复用分别是什么

| 你想留下的东西 | 合适的保存方式 | 下次怎样使用 |
|---|---|---|
| 一次阅读的完整解释、来源、方法与应用 | 普通 Markdown 或你选择的 Obsidian 知识库 | 让渡鸦从该目录找到并读取相应笔记 |
| 当前项目的服务对象、偏好、已采用方向 | 渡鸦项目记忆 | 说“继续某项目”，读取相关记录 |
| 更新过的课程理解与旧说法的差别 | 新版笔记或单独辨析，保留原来源关系 | 下次先判断版本和适用条件，再引用 |

Obsidian 笔记和 `~/.duya/memory` 是不同位置，不需要把同一篇长文机械保存两遍。你已经选定保存方式时，按你的选择执行；保存后报告实际文件，不只回复“已经永久记住”。

已有同名文件且内容相同，重复保存不应再造一个副本；内容不同则说明冲突，按你的选择另存新版或处理原文，不静默覆盖。没有本地文件权限时，可以先交付 Markdown 内容，但不能声称已写入你的库。

量子阅读只在本次任务中读取、解释、应用和保存。没有你另行要求并实际设置的自动化，不会后台读新课、定期复习或自动同步另一台电脑；知识笔记也不等于模型权重被训练。
