# 一句话更新渡鸦

[返回首页](../README.md) · [完整使用手册](新手入门.md) · [安装指南](安装指南.md)

从 **0.4.0** 起，在正在使用渡鸦的对话里说：

```text
更新
```

也可以说“更新渡鸦”“把 duya-skills 升级到最新版”，或者直接使用 `$duya-update`。渡鸦会检查官方 GitHub，执行适合当前安装方式的更新，再报告版本、备份位置和是否需要重新加载。你不需要自己寻找目录和拼接更新命令。

“更新这篇文章”“更新产品报价”仍然是原来的业务任务。如果当前对话不清楚要更新什么，Agent 会先确认对象。

## 第一次从旧版升级

**0.3.x 及更早版本尚没有这次新增的更新入口与工具。**先用下面一条命令完成一次完整安装，选择你实际使用的客户端：

```bash
npx -y skills add jack-duya/duya-skills -g --skill '*'
```

只使用 Codex 时，可以直接指定：

```bash
npx -y skills add jack-duya/duya-skills -g --skill '*' --agent codex
```

这会安装渡鸦仓库内的主入口、12 个业务快捷入口和更新入口。`--skill '*'` 指这个仓库里的所有 Skill；它不同于把所有 Skill 装到所有客户端的 `--all`。如果曾经自行修改安装目录里的官方提示词，执行外部安装工具前先另存修改；旧版尚不具备本次更新器的自动备份。

安装后按客户端需要新开对话。以后再说“更新”，就使用本页的内置流程。Claude Code 插件用户可以直接按下方原生插件更新方式升级，无需重复装一份独立 Skill。

## 更新时会做什么

1. **定位当前安装。**识别正在调用的 `duya` 核心，以及是否属于普通目录、链接、源码仓库或宿主管理的插件。
2. **检查官方最新提交。**来源固定为 [jack-duya/duya-skills](https://github.com/jack-duya/duya-skills) 的 `main`。版本号取官方包声明，同时比较提交；同一版本号下的修复也能检查到。
3. **下载并校验。**普通安装下载已查到的固定提交包，检查组件清单和必需文件，避免检查时与下载时拿到不同版本。
4. **备份并应用。**完整准备新版后，备份将被替换的渡鸦文件，更新核心并补齐快捷入口；替换失败时尝试恢复原安装。
5. **核对与回报。**说明更新前后版本、提交、实际变化、备份位置与重新加载要求。没有更新则直接告诉你已是最新；失败就报告失败，不把下载成功当成安装成功。

默认跟随官方 `main` 的最新提交，不仅比较 Release 标题。Release 继续提供固定版本的下载包和更新说明。更新仅由你的请求触发，不会在后台设置定时任务。

## 会保留哪些内容

| 内容 | 更新行为 |
|---|---|
| 官方 Skill、方法、主题与工具 | 采用官方最新文件；替换前保存旧文件备份 |
| 你改过的官方文件 | 旧内容保存在备份中，新版官方内容生效；需要沿用的修改可从备份中恢复或合并 |
| 安装目录里的其他个人文件 | 原则上保留；若恰好与新版官方文件同名，旧内容同样进入备份 |
| `~/.duya/memory` 项目记忆 | 不属于更新包，不修改 |
| 你项目里的文章、客户资料与导出文件 | 不修改 |
| 其他 Skill、账号凭证、客户端 MCP 配置 | 不修改 |

备份默认位于 `~/.duya/updates/` 下，按安装位置和本次更新区分。完成后会给出实际位置。不要把“保留自定义”理解成新旧提示词已经自动做过语义合并；这是可恢复的文件备份，后续按你需要合并具体修改。

遇到同名但不属于渡鸦的快捷目录，会停止并说明冲突，不把它当作渡鸦覆盖。独立安装的多份渡鸦也不默认全部同步；更新当前正在使用的安装，及已经指向同一核心的相关链接入口。

## 不同安装方式怎样处理

| 安装方式 | 渡鸦的执行路径 |
|---|---|
| 通用 Skills 工具安装、手动复制 | 内置 Python 更新器处理当前核心和同级快捷入口 |
| 指向同一核心的已有宿主链接 | 更新真实核心，并处理与它对应的快捷入口 |
| 官方 Git 源码仓库 | 检查来源、分支和本地改动，使用可快进的 Git 更新；不会强制重置或清空工作区 |
| Claude Code 插件 | 通过宿主更新市场和插件，不能直接改缓存目录冒充升级 |
| 其他宿主管理的插件 | 使用该宿主实际支持的更新入口；无法自动执行时，明确指出剩余操作 |

Claude Code 插件的原生命令如下；有终端能力且安装已确认时，由 Agent 执行即可：

```bash
claude plugin marketplace update duya-skills
claude plugin update duya@duya-skills
```

若宿主没有开放插件更新工具，或者需要由你在界面中操作，渡鸦会说明实际限制，不能承诺在所有客户端中都完全自动。普通安装更新需要 Python 3.10+、GitHub 网络访问与当前技能目录的写入权限。

## 只检查、不更新

```text
检查渡鸦有没有新版，先不要安装。
```

这次只读取本地版本和 GitHub 信息，不替换文件。遇到网络失败会报告检查失败，不会据此判断“已经最新”。

## 更新后为什么还要新开对话

文件更新和模型当前加载的提示词不是同一件事。部分客户端会继续沿用当前对话已经读取的旧指令，也可能在新开对话时才发现新增的快捷入口。按客户端要求重新加载或新开对话，再使用 `$duya-video`、`$duya-wechat` 等命令。

更新器记录的版本以当前核心的 `package.json` 和本次更新状态为准。它不会伪造其他安装工具的全局锁文件；外部工具自己的更新时间可能与内置更新记录不同。排查时以实际文件和这次更新结果为依据。

## 常见问题

- **连不上 GitHub：**检查网络后重试；失败时保留原安装。
- **有本地 Git 改动：**先查看并保存具体改动，再处理更新；不要用强制重置解决。
- **提示同名 Skill 冲突：**确认那个目录的用途，不能为了升级删掉别人的 Skill。
- **更新后不满意：**使用本次返回的备份恢复或提取自己的改动；先保留新版，避免再次覆盖未保存内容。
- **只看到主入口：**确认是否完整安装了 14 个入口，以及客户端是否需要重新加载。只装 `duya` 仍可自然对话完成全部业务工作。

具体实现与故障处理见 [Skill 内的更新工作流](../skills/duya/references/update.md)。
