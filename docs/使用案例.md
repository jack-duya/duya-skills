# duya-skills 使用案例

这篇用连续对话说明怎样把问题交给墨涅斯、怎样看交付是否有用、怎样继续修改。所有人物、业务条件和成稿均为**教学示意**，没有把示范写成真实客户案例或已验证的获客成绩。

示例使用 Codex 的 `$duya`。其他客户端换成对应入口即可，参见 [安装指南](安装指南.md)。每个案例都可以单独使用，不要求按顺序完成。

## 案例一：家庭保洁新号，从起步方向走到第一条内容

### 你可以这样开始

```text
$duya 我做本地家庭日常保洁，想从小红书开始。
我们能拍实际清洁过程，暂时一个人做内容，不想正脸口播。
新号不想一上来全是服务介绍，希望先用和家庭生活有关的内容让合适的人愿意看。
帮我给 5 个有区别的选题，选择最适合先做的一条，找参考后写成完整内容。
```

这轮已经指定平台与阶段，不需要再从所有平台重新选起。关键是把“家庭日常保洁”转成相关人愿意看的生活问题，再考虑用哪些真实材料支持表达。

### 这次工作应该怎样展开

墨涅斯会沿用“商家、不出镜、能拍过程”这些条件，从家庭生活和家务处境找入口。需要参考时实际检索模板库，检查参考是否适合商家身份；没有完全匹配的保洁模板，可以借相近生活场景的结构。

同一批选题可以承担不同任务。例如：

| 选题 | 相关的人为什么愿意看 | 适合的材料 |
|---|---|---|
| 家务最累的瞬间：刚干完，又像没干 | 说中家务反复发生、付出不被看见的处境 | 刚收好又出现使用痕迹的日常场景，透明标为情景演示也可以 |
| 客人来之前，先收拾哪里才不至于越忙越乱 | 给时间有限的人一个具体判断 | 实际收拾过程、区域对照 |
| 第一次请保洁，哪些地方最好下单前说清 | 帮已经考虑购买的人减少理解偏差 | 真实服务范围、可公开的说明 |
| 看上去挺干净，为什么你还总觉得没收拾好 | 把“乱、脏、物品多”分开解释 | 真实区域与对应处理过程 |
| 想找人帮忙做家务，最难开口的到底是什么 | 围绕家庭分工和个人顾虑形成讨论 | 观点文字或明确的情景演示，不编客户原话 |

不是每条都要马上介绍服务。第一条可以先完成一个有相关性的观看和讨论任务；第三条再回答已经准备选择服务的人。

### 一份可交付的成稿示意

**首选题目：** 家务最累的瞬间：刚干完，又像没干

**封面文字：**

> 地还没干，鞋印先来了。

**正文：**

> 地还没干，鞋印先来了。
>
> 水槽刚洗好，又放进来一个带着奶渍的杯子。
>
> 快递箱刚收走，桌上又多了一层拆下来的包装。
>
> 每一件都不算大事，但刚才那个忙了半天的人，已经不想说话了。
>
> 再听一句“这不是挺干净的吗”，更不知道从哪儿解释。
>
> 对，就是因为刚收拾过。
>
> 家务有时候最累的，是它很少留下一个“我做完了”的时刻。你刚以为能歇一会儿，下一轮已经开始了。

**商家身份的首评：**

> 我们做家庭保洁，也会在这里聊日常家务。你最不想马上重来一遍的是哪件活？拖地、收厨房，还是刚叠好的衣服？

**制作说明：** 用确实拍得到的居家或清洁场景配字；如果拍的是演示场景，按演示呈现。没有实际客户家庭素材时，不把镜头或文字包装成客户家的亲历故事。

上面是一种表达示范，并没有声称取自某条真实在线模板。实际使用中，若你要求找参考，答复应附本次真正取得的参考编号和改编理由。

### 你可以怎样继续

```text
这个方向可以。保留“刚收拾过却像没干过”的处境，压成一张图能放下的文字。
```

或者继续做不同任务的内容：

```text
继续做“第一次请保洁，下单前说清什么”。这条面向已经有需求的人。
我把实际服务范围给你，按这些事实写，不要沿用上一条的情绪表达：……
```

同一个账号可以有不同的内容任务。沿用相同受众和业务事实，不等于每一条都套同一个情绪开头。

## 案例二：装修视频有播放，但吸引的是同行

### 先把原稿和目标一起交出来

```text
$duya 我做本地装修，想吸引准备装修的业主。
最近视频播放还可以，但评论都是同行在争工艺。
原稿是：“今天带大家看一下我们卫生间墙面处理的标准流程，第一步清理基层，第二步……”
我有真实施工和检查素材，老板可以做短旁白。
帮我判断问题，再把这条改成业主愿意看、也能理解我们服务的一条视频。
```

### 有用的判断应该具体到这里

原稿从“工艺流程”进入，愿意停下来的人可能是研究工艺的人。业主也可能在意质量，但更直接的判断通常是：自己看不懂施工时，怎么知道做了什么、出了问题找谁、哪些承诺能检查。

这时先把专业过程翻译成业主的选择问题，比原封不动多发几个账号更有针对性。这个判断仍然基于当前文案；如果实际情况是已有很多合适业主咨询、只是新区域覆盖不足，扩分发就可能成为优先项。

### 改成能拍的版本

**开头：**

> 工地群每天发照片，你都回“收到”。但照片里到底做了什么，你真看懂了吗？

**中段旁白：**

> 一张刷好的墙，能让你看到最后的样子，看不到中间每一步。
>
> 所以别只问“今天做完了吗”。先和施工方说清楚：哪些过程你想了解，哪些位置要拍近一点，哪一步要等确认再往下做。
>
> 照片发来，你至少能对上三件事：这是家里的哪儿，正在做什么，下一步要确认什么。
>
> 不然每天几十张图，你觉得自己一直在跟进，真问起来，只记得“今天又施工了”。

**结尾：**

> 找装修公司时，也问一句：我不懂工艺，也没空天天到场，你们准备怎么让我看明白？

| 段落 | 使用什么画面 | 拍摄要求 |
|---|---|---|
| 开头 | 当前工地全景或老板短出镜 | 明确是实际可展示的现场 |
| “只看最后结果” | 可用的完工局部 | 不把不同项目拼成同一现场的前后对比 |
| “对上三件事” | 正在处理的位置、已有检查素材 | 用字幕说明实际位置与动作，不编造尚未确认的工序 |
| 结尾 | 老板一句总结或字幕 | 不添加并不存在的交付制度 |

这条把观看入口从“看我多专业”改成“每天收到工地图，但看不懂”。画面负责展示真实过程，旁白负责解释业主为什么在意。照片帮助理解过程，不能替代实际需要的现场检查；这句话属于给经营者的制作说明，不需要硬塞进口播。企业确实提供对应服务时，再据实加一句自己的做法。

### 后续怎么提修改

```text
开头对了，但我们还没有完整的过程记录制度。
保留给业主的判断方法，别暗示我们已经提供了全套服务。
```

或者：

```text
我们确实会留这些过程记录，我给你一个真实示例。
把稿子改成用这个案例说清楚，时长控制在老板能自然说完的范围内：……
```

新材料决定能增加哪些证明，不通过夸大承诺补足说服力。

## 案例三：抖音号不够用，要不要买更多账号

### 一个不需要包装得很专业的问题

```text
$duya 抖音账号不够用了，在哪买账号？
我们是做装修获客的，现在几个人轮着发，想多来一些合适的业主咨询。
```

这里需要理解买账号背后的业务目的。墨涅斯应给出判断和选择依据，不只是采购指路，也不该长篇反问之后不解决任何问题。

### 一份合理答复应给判断，也给办法

> 你真正想增加的是合适的业主咨询。买号只是其中一个办法，先别把“号不够”直接当成“咨询少”的原因。
>
> 仅按现在的信息，我会先弄清现有号有没有一类能反复做、也能吸引业主的内容。比如讲工艺，容易把讨论留在工艺上；换成业主正在担心的事——报价包含什么、不到工地怎样了解过程、出了问题谁来处理——再用真实素材回答，才有机会让观看和选择服务接起来。
>
> 分发上我会这样选：自己能持续取材，就先用现有账号把这种内容做出来；缺本地真实体验和额外触达，可以找适合的素人合作；需要对方已有受众和信任，再看达人合作。已有内容带来合适咨询、现在只是地区或人群覆盖不足，就可以扩大自营矩阵。
>
> 所以我现在的首选是先定“值得复制的内容是什么”，再决定复制到多少号、由谁发。你给我一条现有稿，我会先把它改成业主愿意看、也能看懂服务价值的版本。

三种方式的具体取舍应当讲清楚：

| 方式 | 在什么情况下有用 | 你仍然要解决什么 |
|---|---|---|
| 自营账号与矩阵 | 真实素材和内容供给稳定，希望掌握表达与分发 | 谁持续取材、制作、维护，每个号增加什么覆盖 |
| 素人合作分发 | 希望增加与目标人群相关的真实体验和场景 | 找到适合的人、安排真实体验、写清合作与内容要求 |
| 达人合作 | 需要对方现有受众、表达能力或信任关系 | 受众是否匹配，合作内容能否说明真实购买理由 |

这里没有把任何方式列为永远的最优解。比如你随后补充：

```text
现在内容还没有稳定带来业主咨询。我们有很多施工素材，但每条都拍得像工艺教学。
```

下一步应该进入具体改稿和生产形式，而不是继续讨论账号渠道。可以直接要求：

```text
按这个判断，先用我已有素材做 3 条不同的业主选题，把其中一条写成完整稿。
```

### 如果你提供了相反的事实

```text
现有账号已经持续有合适咨询，老板也能提供素材。
现在新增了两家真实门店，想让当地人分别看到当地现场。
```

建议就应该变化。此时可以帮助你设计门店账号角色、取材分工和总部制作方式，支持有明确用途的扩张。

由果推因、由因解果的价值，是让办法匹配真正的问题。它不是一句“账号多没用”，也不是永远要求你先做商业诊断。

## 案例四：从模板研究到小红书成稿

### 直接要求把链路做完

```text
$duya 我做家庭保洁，想写“第一次请保洁，下单前怎么说清需求”。
去模板库找合适参考，没有完全同赛道也可以用相似需求的结构。
我是商家，不假装消费者。给最终标题、封面、完整正文和首评。
```

### 你应该看到什么

工具能正常访问时，答复应该给出本次取得的参考编号、可迁移的结构以及完整稿。选择依据可以是“让首次购买者提前确认容易理解不一致的事项”，而不只是“这条点赞多”。

如果参考是消费者求推荐，不能直接把保洁商家写成“大家救救我，求一家靠谱保洁”。可以研究求助内容为什么引发参与，再转为符合商家身份的解释。

### 成稿示意

**标题：** 第一次请保洁，先问清“全屋”到底算哪儿

**封面：**

> 下单前，把这 4 件事说清楚

**正文：**

> 你说“全屋打扫”，脑子里想的是柜子、窗户、厨房，都弄一遍。
>
> 对方说的“全屋”，也包含这些吗？先别等人上门了再确认。
>
> 第一次下单，可以直接把这几句话发过去：
>
> **“我这次最想处理的是厨房，其他区域按日常清洁安排，可以吗？”** 先说最在意的地方，别让双方各自猜重点。
>
> **“柜子里面、窗户和家电内部，这次包含哪些？”** 哪些不包含、需要另约什么，当场说清楚。
>
> **“我家现在是这个状态，按这次服务能处理到哪里？”** 把实际照片发过去，日常居住、搬家和装修后的现场分别说明。
>
> **“如果现场发现有些地方做不了，或者要另外安排，先怎么沟通？”** 比起做着做着才知道，提前问一句更好商量。
>
> 价格当然要问，但范围也要一起问。先知道对方准备打扫到哪里，再比较这次钱花得值不值。

**商家首评：**

> 我们做家庭保洁。这篇先把首次下单常见的沟通点讲清楚；具体是否包含某项，请以每家实际服务范围为准。

实际为你的业务创作时，把其中的通用说明替换成你确实提供的服务边界。上面是独立教学稿，不对应一个假造的模板编号。

### 继续调整时不用重新讲一遍

```text
正文保留，但标题太强硬。改成更像第一次下单前的提醒，给我一个首选和两个备选。
```

本轮只应修改标题，不用重新研究产品、重写正文或再次检索同一批参考。

## 案例五：老板忙不过来，线上团队先招谁

### 把现有分工说具体

```text
$duya 我做装修获客陪跑，团队有我和一名剪辑。
剪辑能独立完成成片，但每次都等我给选题、问客户要素材、写稿。
我每天被这些事绑住，想再招一个人。
帮我判断先招什么能力，给具体分工，再写一个招聘试做任务和评价方法。
```

### 判断应该落到工作，而不仅是岗位名

在这组条件下，最值得先补的可能是能从客户业务里取材、形成选题并组织成稿的能力。再增加一个只等稿件的剪辑，可能继续等待同一个瓶颈。

但如果你补充“选题与可用素材已经积压，只是剪不完”，首选就应变成制作产能。岗位选择跟着事实改变。

### 一份可以开始用的分工示意

| 工作 | 主要承担者 | 要交出的东西 |
|---|---|---|
| 确认客户卖什么、服务谁、承诺什么 | 业务负责人 | 已确认的业务边界和典型客户处境 |
| 从采访与现有素材找选题 | 新增的内容策划角色 | 具体切口、为什么给这类人看、用哪些真实素材 |
| 组织旁白或短口播 | 内容策划角色 | 完整稿及素材位置，需要负责人确认的业务句子 |
| 制作与表达实现 | 剪辑 | 按已确认判断完成成片，并指出素材缺口 |
| 核实关键业务事实 | 业务负责人 | 对服务承诺、案例事实的具体确认，不把所有细节重新做一遍 |

小团队允许兼岗，关键是让每次交接带着可执行的材料。

### 招聘时可以这样试做

给候选人同一份材料包：一段真实老板采访、三段可用现场素材、实际服务范围。不要求他们猜业务，也不靠无来源案例填空。

**试做要求：**

> 请从材料里选一个值得讲给潜在客户的问题。
>
> 写出你优先选择的人群处境与理由，再交一条完整短视频稿，标明需要的素材。最后说明哪些句子需要业务负责人确认。

**评价看什么：**

- 有没有分清你的客户与客户的消费者，作品写给谁。
- 选题是否来自材料，是否能解释相关的人为什么愿意看。
- 能否把业务优势变成用户的判断，避免只有公司自夸。
- 稿件是否用现有素材拍得出来，有没有编造案例与承诺。
- 收到一句具体反馈后，能否改到问题本身。

**可以给候选人的反馈示例：**

> 这条还在讲剪辑技巧，我们的客户是找获客陪跑的装修老板。请把开头换成“老板每天改稿但内容还是不来业主”这个处境，并用采访里的取材方式解释怎么改善。不要承诺固定咨询量。

这个任务让你观察独立判断、取材和修改能力。它比让候选人介绍“自己多懂网感”更接近实际工作。

### 新人进来后怎么接着问

```text
这个人已经会从采访里写出可用稿，但判断客户需求还不稳定。
给我一套用现有客户材料带他的训练安排，直接示范一次怎样反馈。
```

训练按当前能力展开，不机械规定入职第几天必须成为操盘手。

## 案例六：一组素材，做成有差异的矩阵内容

### 提供真实素材和生产限制

```text
$duya 我有一组家庭保洁的真实素材：清理灶台边角、处理台面、收好工具后检查。
没有客户口述，也没有前后效果对比。
帮我做 3 条角度不同的内容，一个人能制作。
不要只是同一稿换标题，也别编出素材里没有的过程。
```

### 先决定复制什么

可以共用素材与服务事实，但分别解决不同问题：

| 内容 | 主要问题 | 可采用的形式 |
|---|---|---|
| 边角为什么容易被留到最后 | 日常清洁中的观察与做法 | 过程字幕，围绕实际动作展开 |
| 请人做保洁，先说清重点区域 | 首次购买时的沟通判断 | 短图文或实拍旁白 |
| 做完以后，你会再看一遍哪里 | 对收尾检查的理解 | 用真实检查镜头解释能看见的动作 |

同一批镜头的价值在不同的观看问题里被展开。因为没有客户口述，就不写“客户惊呼”；因为没有前后对照，就不写成完整效果对比案例。

### 同一轮给出三条成稿

**第一条：台面擦完了，眼睛再往边上看一点**

> 大面擦完，看着已经很清爽了。
>
> 先别急着结束，再看看灶台的边角。
>
> 平时最容易顺手擦过的地方，和真正需要多花一点时间的地方，不一定是同一块。
>
> 家里打扫也是这样。觉得“差不多了”的时候，再看看这些不起眼的位置。

**镜头：** 先用处理台面的实际片段，再接灶台边角的清理近景。只有局部过程，不另造整屋前后效果。

**第二条：请保洁之前，先说一句“我最在意这里”**

> 请人来打扫，不用只说“全屋做一下”。
>
> 如果你最在意的是厨房，就直接说：这次我最想处理的是灶台和周围这些位置，按这项服务能做到哪里？
>
> 有些地方你特别在意，但对方不知道。把重点说出来，再把包含和不包含的范围问清楚。
>
> 同样是“来打扫一下”，先把心里那块最想解决的地方说具体。

**镜头：** 台面与灶台边角各用一个实际片段，字幕对应“重点区域”和“服务范围”。这是下单沟通建议，不写成曾经发生的客户故事。

**第三条：工具收起来以后，为什么还要回头看一眼**

> 工具已经收起来了，最后再看一遍刚处理的位置。
>
> 做的时候，眼睛跟着手走；停下来再看，才能换成“这一块现在怎么样”的视角。
>
> 有没有需要补一下的地方？有没有现场就该说清楚的情况？
>
> 收尾检查，就把这几件事留在走之前。

**镜头：** 用收好工具后检查的实际素材，按可见动作配字。不替镜头补写顾客评价，也不把一次检查说成某种结果保证。

三条分别提供观察、购买前沟通和过程理解，素材可以共用，观看理由不同。矩阵与量产能力安排差异和制作，图文或视频能力负责把每一条写完整；不必再发一轮“请继续成稿”。

后续可以直接提局部反馈：

```text
保留第二条，压成一张图。第一条的观点太轻，再给一个更有意思的开头，仍然只用现有镜头。
```

如果后面需要多门店分发，再补充各店真实差异和人员条件，决定账号角色。内容量产并不自动要求更多账号。

## 案例七：量子阅读，把一门课接到自己的业务

**想先看完整成品：**[量子阅读详细教程](量子阅读.md#完整静态示例保洁内容该先讲情绪还是直接讲服务)提供一套保洁教学原料，展示材料审查、方法与边界、两条完整应用稿、五篇知识笔记与索引，以及下一次检索后按服务清单写回复。[原料文件](../skills/duya/assets/learning/sample-source.md)和[示例笔记库](learning-example/)都可以直接阅读。它们是静态教学示范，不是实际获客成绩。

### 别只要求“总结一下”

```text
$duya-learning 读这份课程资料。
我目前做装修公司的获客陪跑，最想解决的是客户内容总在讲工艺，难以让业主理解购买理由。
提炼这门课能帮上忙的方法，说明适用条件和反例。
然后用我这条旧稿演示怎样改，把值得以后继续用的方法保存到“装修陪跑”项目。
```

这段要求给了阅读的应用方向，也明确要完成示范和保存。系统应先了解资料结构与实际覆盖情况，再将知识接到任务。

### 有用的知识条目长什么样

假设资料里有“内容要从客户需求出发”的观点，好的提炼要继续回答：

| 要素 | 条目应该说清楚什么 |
|---|---|
| 要解决的问题 | 专业内容讲得很多，客户却不知道与自己的选择有什么关系 |
| 关键判断 | 客户发生了什么事、正在比较什么、还不理解哪一点 |
| 具体做法 | 把现有工艺信息连接到业主的顾虑或选择，再用真实过程解释 |
| 应用示范 | 将一段工艺教学改成“你不在现场时，怎样知道约定的过程做了什么” |
| 条件 | 目标是业主决策，手中有能支持解释的真实材料 |
| 反例 | 面向工艺培训学员时，步骤教学本身就可能是需要的内容 |
| 来源 | 本次实际读到的资料、章节和作者原意；自己的推断另外标明 |

这样保存的是以后能用对的方法，而不是只存一句口号。

### 新方法与旧经验冲突怎么办

继续说：

```text
这门课强调精准需求，但我们也用泛垂直内容起号。
不要急着选边，比较它们分别解决什么问题，给出什么情况下用哪种，再改刚才的方法条目。
```

这时应检查两种方法是否服务不同的内容任务：相关人愿意看、进一步理解、比较和准备咨询，可能需要不同表达。只有在相同目标与条件下给出相反建议，才是真正需要处理的冲突。

“泛垂直”不能变成什么热点都蹭，“精准”也不等于每条内容都写成服务广告。方法的使用条件比一个总口号更有用。

### 需要跨对话继续时

```text
记住：本项目服务装修老板，交付获客陪跑，不代拍。
采用刚才的方法，但不承诺咨询数量。
保存成功后给我项目名称和位置。
```

下一次说：

```text
$duya 继续“装修陪跑”项目。
沿用上次保存的内容判断，分析这份新采访，再给两个选题：……
```

当环境能读写文件并运行记忆工具时，应实际恢复相关记录。换设备使用，需要迁移相应记忆目录；仅重新安装插件，不会凭空出现另一台电脑的项目档案。

### 阅读结果也可以存到 Obsidian

如果你习惯在 Obsidian 中看长文、回查来源和浏览笔记关联，可以继续说：

```text
$duya-learning 把这次完整阅读结果和应用笔记保存到我选定的 Obsidian 库：D:/我的知识库。
先看已有相关笔记，沿用原分类；把资料原意、整合判断和应用示例分清。
保留真正有用的关联，不制造空概念，也不要覆盖同名旧文或修改知识库配置。
给我实际文件位置和一篇阅读入口。
```

已经在当前对话中选定的库直接使用，不必重复给路径。没有指定库时，先确认位置或查看候选；存在多个库时不能随意选一个。没有 Obsidian，也可以把最后一句改成“给我普通 Markdown，保存到这个文件夹”。

保存以后可以这样复用：

```text
$duya-learning 从这个知识库找到我们上次关于“精准需求与泛垂直入口”的方法。
实际读取相关笔记和边界，再看这段新采访应该选什么内容入口。
给两个选题，并把首选写成完整短视频：……
```

这一轮应先找到已保存的方法，再判断新情境是否满足条件。找不到就说明具体缺失，不能临时生成一段话却声称已经检索旧笔记。Obsidian 保存不需要额外 MCP，文件写入与图谱查看方法见[完整教程](量子阅读.md#存进-obsidian-后怎么看)。

## 看结果时，抓住这几个问题

使用示例可以自由改写，不需要背提示词。拿到结果后，主要看：

1. 它是不是在解决你实际做的这门生意，有没有认错你的客户？
2. 首选建议是否有具体理由，人手与素材能不能支持？
3. 文案是不是让相关的人愿意看，后面的展开有没有兑现开头？
4. 要的是成稿，是否真的给了完整稿，而不只是一套结构？
5. 你纠正以后，后续内容是否沿用了新事实？

发现问题，直接指出具体句子或限制，继续让它改。真实业务结果可以帮助进一步判断；这些教学示例本身不代表某种打法已经获得播放或客户转化。
